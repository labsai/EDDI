## 🚀 release: 6.7.1, Java4Shell mitigation, operator activation and 6.7.0 fixes (2026-11-21)

**Repo:** EDDI (`release/6.7.1`, work branches `fix/6.7.1-backports` and `fix/6.7.1-security-backports`)

### What it is

A patch release cut from the `6.7.0` tag, not from `main`. It contains only commits that were already
reviewed and merged on `main`, cherry-picked with `-x` so every commit names its original. Nothing from
`main` that is not listed here is in 6.7.1.

### Found in the pre-release review

Three independent reviews of `6.7.0..release/6.7.1` found no defect in the backported code other than the `*`
gap below. They found that two security fixes already on `main` were missing, and those were added: #1322 and
#1339 above, both clean cherry-picks. Two more things were fixed on the release branch only:

- `Unknown` also strips `*` from an unknown word. A lone `*` became `unknown(*)`, and `*` is the wildcard
  `Expression.equals` honours, so it matched every rule written as `unknown(x)`. `UserInputExpressionRoundTripTest`
  covers it. `main` has the same gap, and the fix goes there separately.
- Docs: the "Behaviour changes in 6.7.1" list in [`upgrading-from-6.5.md`](../upgrading-from-6.5.md#behaviour-changes-in-671)
  gains the workspace, ingestion, import and sync, and Helm Keycloak digest changes, and says that GPT-6.2 and
  Gemini 4 have no reference price yet. It also says that the `unknown(...)` change closes an expression injection
  in 6.7.0, and no longer claims the Vertex picker dropped `gemini-2.5-*`, which it never offered.
  `OpenAiPermitModeAuthMechanism` is `@since 6.7.1`.

The other fixes on `main` that 6.7.1 lacks, for bugs that 6.7.0 has as well, are left for 6.7.2.
