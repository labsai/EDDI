## 🧰 chore(ui): one npm workspace and one lockfile for both UIs (2026-11-04)

**Repo:** EDDI (`chore/ui-npm-workspaces`, stacked on `perf/frontend-phase0-baseline`)

Phase 1a of the frontend unification plan (revision 3, `planning/frontend-unification-plan.md` §2.7, §3.1, §7 phase 1, D2): `ui/` becomes an npm workspaces root, so the Manager, the Chat UI and the shared packages still to come (`ui/packages/*`) install from one lockfile. Both apps stay where they are (D2). `@eddi/core` is the next step and is not part of this change.

### What changed and why

- **Workspaces root.** [`ui/package.json`](../../ui/package.json) declares the workspaces `manager`, `chat` and `packages/*`. [`ui/package-lock.json`](../../ui/package-lock.json) replaces `ui/manager/package-lock.json` and `ui/chat/package-lock.json`. `npm ci` now runs once, at `ui/`, and installs into `ui/node_modules`. Each app keeps its own scripts (`npm run dev`, `test`, `build`, `lint`, `budget`) in its own directory. [`ui/packages/README.md`](../../ui/packages/README.md) holds the place for the shared packages.
- **The lock was seeded from the two old lockfiles, not resolved afresh.** Every version CI had accepted was kept, except the edges the alignment below forced. The resulting lock passes `npm ci` and a clean `npm ls --all` on Linux with Node 26.13.0, as CI runs it. The only transitive version changes are Tailwind 4.3.3 → 4.3.4 (with its oxide platform packages and their `@emnapi/*` children), `enhanced-resolve` 5.26.0 → 5.26.1 and one `magic-string` 1.4.5 where two copies were.
- **Shared versions aligned**, so a dependency both apps use is installed once: `lucide-react` ^0.577 → ^1.59 in the Chat UI (no icon it uses was renamed; typecheck, tests and build pass unchanged), `jsdom` ~30.1.2 in the Chat UI, and `eslint` ^10.14.0, `typescript` ~5.9.3, `typescript-eslint` ^8.72.1 and `vite` ^8.3.5 in the Manager.
- **`overrides` moved to the root.** npm reads them only from the workspace root. The two `$dompurify`/`$katex` references became explicit floors (`^3.4.17`, `^0.19.1`), because a `$` reference may only name a dependency of the root package itself.
- **Shared configs, without changing what they check.** [`ui/tsconfig.base.json`](../../ui/tsconfig.base.json) holds the eight compiler options every app tsconfig set identically; each `tsconfig.*.json` extends it and keeps its own target, lib and paths. `tsc --showConfig` is identical before and after for all six projects. [`ui/eslint.config.base.js`](../../ui/eslint.config.base.js) holds the recommended presets, browser globals, the two hook rules and the `toBeGreaterThanOrEqual(0)` guard. `eslint --print-config` is identical before and after for nine sample files across both apps, except that the Chat UI's tautology message is now the Manager's longer one. `ecmaVersion` stays per app (2020 and 2022).
- **The Windows `oxide-wasm32-wasi` trap, checked in CI.** npm on Windows prunes that optional package's children from the lock, and the Linux runner then fails `npm ci`. Until now only `ui/manager/AGENTS.md` described a manual check. [`ui/scripts/check-lockfile-platforms.mjs`](../../ui/scripts/check-lockfile-platforms.mjs) (`npm run lockfile:check` at `ui/`) asserts the four children resolve from the oxide package, and that every dependency of every lock entry resolves the way Node would look it up. `UI Manager Checks` runs it after `npm ci`. Run against a copy of the old Manager lock with the children removed, it fails and names all four.
- **Maven.** `pom.xml` runs one `npm ci` (execution `ui-install`, working directory `ui/`) instead of `manager-install` and `chat-install`. Node still lands in `ui/node/<version>`, and `manager-build`, `chat-build` and `copy-ui-bundles` are unchanged, so the jar's `META-INF/resources` layout is unchanged.
- **CI** ([`ci.yml`](../../.github/workflows/ci.yml)). `UI Manager Checks`, `UI Manager E2E (MSW)`, `UI Chat`, `Backend E2E` and `Auth E2E (Keycloak)` install at `ui/` and key the npm cache on `ui/package-lock.json`, as does `Build Image`. The CycloneDX step still writes `bom-ui-manager.json` and `bom-ui-chat.json`, now from `ui/package.json` with `--workspace manager|chat`: each document lists only that app's production dependencies, and its root component is the workspace root (`eddi-ui`), with the app as a component. Trivy and Gitleaks scan the whole repository and needed no change. CodeQL's UI config adds `ui/packages`.
- **Dependabot.** The `/ui/manager` and `/ui/chat` entries become one `/ui` entry with the Manager's groups and ignore rules, so a dependency both apps use moves in one PR.
- **Elsewhere.** The auto-approve policy protects `ui/package*.json`, `ui/scripts/**`, the two base configs, `ui/bundle-budget.json` and `ui/packages/*/package*.json` (with `AutoApproveCopilotPolicyTest`). `.gitignore` ignores `ui/node_modules/`. `.gitattributes` pins the root lock to LF. The demo Dockerfile, the Manager's `mise.toml` install task, the Stryker schema path and the design-sync `extraFonts` path follow the new layout. The root, Manager and Chat UI `AGENTS.md`, both READMEs, `CONTRIBUTING.md`, `docs/agent-manager-gui.md` and `docs/developer-quickstart.md` say to run `npm ci` in `ui/`.

### Not done, or not verified

- The CI jobs were not run. Locally: `npm ci` at `ui/` (Windows, Node 24), both apps' lint, typecheck, unit tests, `vite build` and `npm run budget` (`/manage` 616.4 KB gz, `/chat` 161.6 KB gz, both within the phase-0 budgets), the Manager's `audit:prod` and `i18n:check`, and the CycloneDX step in a `node:26.13.0` container. The Manager's only failing unit tests are the three in `resource-detail-rag-upload-source.test.tsx` that already fail locally on `main`.
- **Jar layout.** `./mvnw package -DskipTests` on this branch and on `perf/frontend-phase0-baseline` both put 947 entries under `META-INF/resources`. 842 paths are identical, and the other 105 differ only in a Vite content hash; with hashes normalised, the two listings are the same.
- `BuildQualityGatesTest.vitestIsGroupedForSecurityUpdates` now expects at least one npm entry grouping vitest, since there is one `/ui` entry instead of two.
- `npm audit` run from `ui/manager` (`audit:prod`) now audits the whole workspace tree, the Chat UI's production dependencies included.
- Not run: the Manager's Playwright tiers, Stryker, and the design-sync converter.
