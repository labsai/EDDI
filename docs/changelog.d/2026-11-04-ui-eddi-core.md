## 🧩 refactor(ui): `@eddi/core`, and the 1:1 turn loops on it (2026-11-04)

**Repo:** EDDI (`refactor/ui-eddi-core`, stacked on `chore/ui-npm-workspaces`)

Phase 1b of the frontend unification plan (revision 3, `planning/frontend-unification-plan.md` §1.3, §2.7, §3.1, §3.2, §7 phase 1, §9): the first shared package, `@eddi/core` under [`ui/packages/core`](../../ui/packages/core/README.md), with the union of the turn loops' protocol tests, and the widget and the Manager's `ChatPanel` moved onto it.

### What changed and why

- **`@eddi/core`** — framework-free TypeScript, no React and no DOM beyond `fetch`, consumed as source through the workspace link (`exports` → `src/index.ts`; no build step). Every module was derived from code the apps already had twice or three times, not written afresh:
  - `http.ts`: `HttpClient` — status-aware fetch, `ApiError`, the `{error, code}` envelope (`errorPayload`), an injected `AuthProvider` with one 401 retry, and an injectable transport and error factory, so an app keeps its own error type. The module-level `setBaseUrl` / `setAuthToken` / `setUnauthorizedHandler` / `request` drive a default client, the way the Chat UI always used this layer.
  - `sse.ts`: **one** frame parser and stream reader for agent and group streams, replacing three that each got a different subset right. It strips exactly one delimiter space, joins multi-line `data:`, normalises CRLF on the accumulated buffer (so a `\r\n` split across two reads still splits the frame), accepts bare CR, flushes the decoder and the last unterminated frame at EOF, and skips frames with no `event:` line where the caller asks (group streams). The two readers that disagreed: the Manager's chat reader did not flush the decoder; the Chat UI's `.trim()`med event names. The package follows the majority (flush) and the spec (one optional space).
  - `conversation.ts`: start, read, send, stream, undo, redo, rerun, end, the managed variants and the profile, as `createConversationApi(http)` plus bound functions over the default client. `hitl.ts`: approval status, cancel, resume, deadline maths, poll cadence. `stream-events.ts`: error frames, `UNCONSUMED_STREAM_ERROR_CODES`, tool names, `inputField`, dropped vs paused turns, output texts and images. `snapshot.ts`, `attachments.ts`, `ratings.ts` (with `createRatingClient(http, channel)`), `rating-steps.ts` (the rule the two apps held twice, with the union of their "belongs to no step" and "not ratable" predicates) and `types.ts` (ten SSE events — `guardrail_triggered` was missing from the Chat UI's list).
  - Its README is the backend contract list that was in `ui/chat/AGENTS.md`, each rule now naming the test that pins it.
- **Tests first.** The Chat UI's protocol suites (`http`, `chat-api`, `sse-events` with its Java-pinned review test, `snapshot`, `hitl-api`, `attachments-api`, `rating-api`, `rating-steps`) and the Manager's `parse-sse-frame` suite moved into the package. [`turn-protocol.test.ts`](../../ui/packages/core/src/turn-protocol.test.ts) encodes the protocol-level cases the five loops' suites (`use-chat`, `use-operator-chat`, the Workforce member thread, `ChatWidget` + `chat-store`) each held in UI terms: a 409 (and a pre-turn `error` code) is a refusal whose input was never consumed, dropped vs paused turns, `inputField` on `done`, undo/redo's empty 200 and 409, rerun's parameters, cancel, resume, the injected auth and error factory, and the framing cases the three readers disagreed on.
- **Boundaries.** `sharedPackage()` in [`ui/eslint.config.base.js`](../../ui/eslint.config.base.js) forbids, in a package, an app import, React, `@eddi/ui` and the DOM globals; [`boundaries.test.ts`](../../ui/packages/core/src/boundaries.test.ts) checks the same over every `ui/packages/*` and fails on an import cycle (its cycle finder is tested against a synthetic one). The package's `tsconfig.json` is as strict as the strictest app (the Manager's `noUncheckedIndexedAccess`, ES2020), because each app compiles it.
- **Widget (`ui/chat`).** `ChatWidget`, `ChatInput`, `PausedCard`, the HITL polling and rating hooks and the store import the protocol from `@eddi/core`. Deleted: `api/http.ts`, `api/chat-api.ts`, `api/sse-events.ts`, `api/snapshot.ts`, `api/attachments-api.ts`, `rating-steps.ts` and their tests. The widget keeps what is its own: `embed-auth.ts`, the brand, the demo, `pauseHeadline` (`api/hitl-api.ts`), the `chat-ui` rating channel and error copy (`api/rating-api.ts`) and `skippedTurnMessage` (`turn-notices.ts`). `@/types` re-exports the contract types. Its consumer tests changed in import paths only; `vite-proxy.test.ts` also scans the package for the path prefixes it calls.
- **Manager (`ui/manager`).** `lib/api/chat.ts` is now the Manager's binding of the package's conversation API: same signatures and message types (the Operator and the Workforce member thread import it too, so neither changed), with an `HttpClient` built on a new `ApiClient.authorizedFetch` (pre-flight refresh, one forced refresh and retry on a 401, network failures as `ApiClientError` status 0, an abort left an `AbortError`) and `apiErrorFromResponse` — so the raw-fetch stream and `text/plain` send now refresh the token like every `api.post`. `startConversation` stays an `api.post`: `ApiClient` also reads a `location` field from the body, which the MSW fixtures rely on. `groups.ts`'s group reader is `readSseStream`; `use-chat.ts` takes `UNCONSUMED_STREAM_ERROR_CODES` and `parseErrorEvent` from the package; `ChatPanel` and `use-chat-ratings` take the rating steps from it. Deleted: `lib/api/sse-utils.ts` (and its test, ported), `lib/chat-rating-steps.ts`.
- **Gates.** CI's `UI Chat` job runs the package's type check, lint and tests. `i18n:check` walks `ui/packages/*/src` (the Manager compiles them). `auto-approve-copilot.yml` protects a package's vitest, ESLint and tsconfig files, as it does an app's (`AutoApproveCopilotPolicyTest`).
- **Archived changelog links.** Eight links in `docs/changelog/2026-09.md` and `2026-10.md` named files this change deletes; they now point at the package module the code moved to (`DocumentationLinksTest`). Only the link targets changed.
- **Platform Operator.** No endpoint, field or failure mode changed, so neither its prompt nor its allow-list needed an update; its code (`use-operator-chat.ts`, `lib/operator`) is untouched (phase 6).
