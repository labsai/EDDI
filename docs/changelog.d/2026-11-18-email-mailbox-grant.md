## ✨ feat(connections): dedicated Google Workspace mailboxes for the email channel — the MAILBOX binding (2026-11-18)

**Repo:** EDDI (`feat/email-mailbox-grant`) — Phase 4 of the email channel v2 plan (`planning/email-channel-v2-plan.md` §8).

An email integration could not read a Google Workspace mailbox: Gmail's IMAP needs an authorization-code grant, and EDDI filed those only `PER_USER`, which a poll (running as nobody) can never use. A connection can now be bound `MAILBOX`: an administrator links each **dedicated** mailbox once by signing in to Google as it, and only the email channel's IMAP/SMTP login can spend that grant.

### What changed and why

- **Model.** `Binding.MAILBOX`, legal only with `OAUTH2_AUTHORIZATION_CODE`; the auth-code flow now accepts `PER_USER` or `MAILBOX`. New `oauth.accountCheck` (`google-gmail-profile`, an enumeration so more providers can follow), required for `MAILBOX` and refused on every other binding; with `google-gmail-profile` the `baseUrlAllowlist` must name `https://gmail.googleapis.com`. A `MAILBOX` connection is refused at the write boundary while `authorization.enabled=false` (nobody could link it), and the startup guard reports that case and a `MAILBOX` connection on any other flow.
- **Grants under `mailbox:<address>`.** One grant per mailbox in the existing grant store, principal `mailbox:<normalised address>`. `mailbox:` joined `ReservedPrincipals.PREFIXES`, so no signed-in user or email identity can carry it, and a GDPR erasure of a `mailbox:` principal is refused like `__service__` (unlinking is a deliberate admin action).
- **One flow, not two.** `POST /connections/{name}/mailbox-grants/authorize` (body `{address}`), `POST …/mailbox-grants/unlink`, `GET …/mailbox-grants`, all `eddi-admin` and checked in code. Authorize writes the same state row, PKCE and nonce cookie as a per-user link, plus the mailbox address and a hash of the admin's own `email` claim (two nullable columns on `connection_oauth_states`, both stores); the existing callback branches on it. It asks Google for `login_hint`, `access_type=offline` and `prompt=consent`.
- **Two checks before anything is stored.** The new token's Gmail profile (`users.getProfile`, fetched by `MailboxAccountCheck` through `OutboundHttp`, no redirect, fixed URL) must be the address — otherwise `?error=mailbox_account_mismatch` (or `mailbox_account_unverified` when it cannot be read); and the address must not be the admin's own — refused at authorize (400) and again at the callback (`mailbox_is_own`). Success writes the audit entry `connection.mailbox.link`; unlink writes `connection.mailbox.unlink`. Shape checks before and after the exchange are keyed on the row's kind, and a discard takes back the grant under the mailbox principal, never the admin's.
- **Resolver.** `resolveMailboxAccessToken(reference, target, address)` is the one way to spend a mailbox grant; `ImapMailTransport` uses it for IMAP and SMTP when the connection is `MAILBOX`. `resolve`, `resolveForDiscovery`, `resolveAccessToken` and `resolveBasicLogin` refuse a `MAILBOX` connection with `UNSUPPORTED_PLACEMENT` before any token is fetched (plus a backstop in `resolvePrincipal`). A missing or provider-rejected grant is `NOT_CONNECTED`.
- **Refresh re-checks the account.** `OAuthTokenService` runs the account check after every refresh of a mailbox grant: a mismatch deletes the grant (`[SECURITY]` log, refresh outcome `account_mismatch`); an unreadable profile keeps the grant and the rotated refresh token but stores the new access token already expired, so it is never served unverified.
- **Email channel.** `MailboxException.Category.NOT_CONNECTED`; such a poll failure also sends the owners a once-a-day notice with the new reason `MAILBOX_NOT_LINKED`. Saving an integration whose MAILBOX connection has no usable grant for its address succeeds with the warning `email.mailbox-not-linked`.
- **Manager.** The connection editor offers *Per user* / *Dedicated mailbox* for the user-login flow and an account-check field; a **Mailbox grants** panel on a MAILBOX connection's page lists, links (disabled while the editor is dirty) and unlinks; the link-result handler reads `?mailboxLinked=` and the three new error codes; email settings offer MAILBOX connections and show whether the integration's address is linked; the new save warning has its text. Keys in all 11 locales.
- **Operator.** Prompt paragraph (how to set up a Workspace mailbox, what `email.mailbox-not-linked` and `NOT_CONNECTED` mean) and `GET /connections/{name}/mailbox-grants` on the read allow-list (the link and unlink POSTs deliberately not); revision 82.
- **Docs.** [Connections → Dedicated mailboxes](../connections.md#dedicated-mailboxes-mailbox), the model, placement, guard, security and metrics tables; [email-integration.md](../email-integration.md#google-workspace-a-dedicated-mailbox-linked-once-by-an-administrator) replaces "Gmail is not supported" with the Google setup and states what deleting an integration and a GDPR erasure do to the grant; [metrics.md](../metrics.md) lists the new outcomes.
- **Tests.** Resolver refusal per entry point, the link flow (success under `mailbox:`, mismatch, unverifiable, own address at authorize and at callback, binding changed meanwhile, discard principal, non-admin and anonymous refused, list, unlink), refresh re-check (match, mismatch deletes, unverifiable keeps), the account check, model validation, startup guard, both OAuth state stores (unit, and `OAuthStateStorePostgresIT`), the IMAP login choice, the poller notice and the save warning. The resolver refusal, the callback's mismatch check, both own-address checks, the refresh mismatch check and the reserved prefix were each mutation-checked: reverting the guard fails its test.

### Not verified yet

Against a real Google Workspace tenant: that `users.getProfile` accepts a token carrying only `https://mail.google.com/`, that an Internal app's refresh tokens do not expire like a Testing app's, and Gmail's handling of the `$EddiProcessed` keyword (plan §13 items 1–2). `EmailImapPollingIT` was not extended with an XOAUTH2 server; the login choice is unit-tested instead.
