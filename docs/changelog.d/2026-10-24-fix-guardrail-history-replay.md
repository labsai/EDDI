## 🔒 fix(guardrails): a blocked message no longer reaches the model on the next turn (2026-10-24)

**Repo:** EDDI (`fix/guardrail-history-replay`)

### What changed and why

Review of the input/output guardrails (#1064, #1112) found that a message the `classifier` guardrail **blocked** was sent to the main model on the following turn. An input block is served as a fallback; the history builder merges a fallback turn's question into the next user message so roles keep alternating; input guardrails treat that merged text as history, and history is only re-screened by guardrails with `screensHistory() == true` — which the classifier is not (one model call per history message would multiply its cost). So: an injection blocked on turn N, then "hi" on turn N+1, and the model received the injection. The same path undid a classifier `redact`.

- **A durable marker, not re-screening.** When an input guardrail blocks — or redacts with a guardrail that does not re-screen history — `LlmTask` flags the step `llm:input_withheld:<taskId>` (`MemoryKeys.LLM_INPUT_WITHHELD_PREFIX`). `ConversationLogGenerator.isInputWithheldStep` reads it (and, for steps written before it existed, an `audit:guardrail:input:*` record with action `block`). Both history paths (`ConversationLogGenerator.generate` with `skipFallbackOutputs`, `ConversationHistoryBuilder.generateMessagesFromOutputs`) replace that turn's user message — text, extracts and input files — with `[earlier message withheld by a guardrail]`, for every guardrail type. The rolling summarizer's input and the recall tool get the same view through `ConversationLogGenerator.modelFacingOutputs`. Memory and the human transcript keep the message.
- **Current-turn text is located structurally.** `AttachmentForwarder` appends extract/note text parts behind the typed text, so "the last text part" used to be the extract: a first-pass redaction was not applied to what the model saw, and the classifier screened the extract instead of the typed text. `LlmTask` now records the typed text's content index before forwarding; `GuardrailService.runInput` applies the (reused) first-pass result to it and screens each attachment text part after it as this turn's input — recorded, able to block.
- **Bounded author regexes.** `regex-filter` and `prompt-injection` patterns run through a shared deadline-checking matcher (the classifier `labelPattern` one, later folded into `RegexDeadline`) with 250 ms per text; past it the guardrail throws `GuardrailUndecidedException("pattern_timeout")`, so `failMode` applies — a `block` guardrail refuses the text instead of passing it. Both types now `validate()` their patterns, so an invalid one fails the deploy instead of being dropped (which left a block-only filter that never fires).
- **Spend gate first.** The spend gate is asked before the input guardrails and retrieval, so an over-budget turn pays no classifier call or embedding query; every guardrail reprompt asks it again.
- **`postResponse` after an input block.** It now runs, as after every other fallback (output block, spend refusal, `onError`), so a `convertToObject` + `addToOutput: false` task whose `postResponse` builds the reply answers the user instead of showing nothing — and the docs' claim that the `fallbackField` shape is what `postResponse` reads is now true for both sides.
- **History-screening cost** is recorded whether or not the guardrail fires.

### Review follow-ups

- **A withheld turn's files stay out too.** `AttachmentContextExtractor.attachmentsFromPreviousTurns` skips withheld steps (no re-inlined image, no "files shared earlier" note), and `ReadAttachmentTool` is built with `withheldStorageRefs` so `listAttachments`/`readAttachment` cannot hand a blocked file's content back as an unscreened tool result.
- **The current turn is not withheld by its own flag** — a second LLM task of the same turn decides it with its own guardrails (both history builders skip the last output index).
- **Spend gate asked twice**: before the input guardrails and again after them, so a classifier's price cannot carry the model call past a ceiling. A turn refused before screening is flagged withheld when a configured input guardrail does not re-screen history (it was never classified).
- **One regex deadline helper.** `BoundedRegex` is folded into `ai.labs.eddi.utils.RegexDeadline` (now with a deadline-preserving `subSequence` and `matcher(...)`); [`security.md`](../security.md#parser-and-matcher-bounds) lists the guardrail patterns' bound. A pattern timeout in a `regex-filter` keeps what the finished patterns found (`GuardrailUndecidedException.partialFinding`): failing open, a `redact` keeps those rewrites and a `block` that matched still blocks.
- **Docs**: template data (`{memory.last.input}`, `{memory.past}`, `{conversationLog}`, captured properties) is *not* filtered — don't template earlier user input into a guarded task's prompt or `httpCall` body; a turn on which the guarded task did not run was never classified.
- Persistence round trip and undo/redo of the flag through the real `ConversationMemory` (`InputWithheldRoundTripTest`); the Platform Operator's guardrail paragraph learned the pattern budget, the deploy-time pattern check and the withheld placeholder.

**Deferred:** a reprompted answer is still not re-run through `responseValidation` (its re-ask loop does not return to the output guardrails, so wiring the two together is not a small change); documented in [`langchain.md`](../langchain.md#where-guardrails-run).
