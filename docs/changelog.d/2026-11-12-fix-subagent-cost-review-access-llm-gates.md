## 🔒 fix(security): delegation cost ceilings, standalone sub-agent cleanup, review and search access, LLM provider authoring (2026-11-12)

**Repo:** EDDI (`fix/subagent-cost-review-access-llm-gates`)

### What changed and why

- **Delegations are held to the caller's cost ceilings.** `converse_with_agent` and `create_sub_agent`'s initial message ran the callee in its own conversation, whose spend reached none of the caller's ceilings (`maxCostPerConversationUsd`, a schedule's `maxCostPerFire`); only the tenant's monthly budget stopped a model that kept delegating. The caller's remaining allowance — its ceiling less the spend recorded so far, an allowance rather than a hard limit, since a task's in-flight spend is not yet recorded — now travels as the reserved context `delegationMaxCostUsd` (added to `ClientContextGuard.RESERVED_KEYS`), which `LlmSpendGate.effectiveCeiling` applies to the callee's turn like `maxCostPerFire`, the tighter one winning; a caller with nothing left does not delegate. After the turn the callee's spend is charged back onto the caller's step as the new `audit:delegated_cost` (`MemoryDelegationBudget`), summed with `audit:cost` and `audit:discarded_cost` by every conversation total — Mongo and Postgres tail reads included — but never metered to the tenant again. The tool loop now re-reads the conversation total each round, so a charge-back mid-loop stops it. See [Group Conversations](../group-conversations.md#cost-ceilings-across-delegations).
- **Sub-agents run on the parent's model unless `allowedModels` says otherwise, and `inheritParentModel=false` inherits no key.** The parent's `${vault:…}` key was handed over whenever the provider matched, even with inheritance off, and an absent `allowedModels` meant any model on that key. Without `allowedModels` a sub-agent now gets the parent's provider and model, and any other choice is refused with a message naming the setting; explicit allow-lists work as before.
- **Standalone sub-agents are torn down with their conversation, and capped per user.** Outside a group nothing removed the agents `create_sub_agent` deployed except the model's own `teardown_agent`. `StandaloneDynamicAgents` now undeploys and permanently deletes the non-retained ones when the creating conversation ends (`endConversation`, a turn that ends it) or is deleted (`ConversationPurgeService`) — only agents whose `dynamicOrigin` names that conversation and no discussion; the group path is untouched. New `eddi.dynamic-agents.standalone.max-live-per-user` (default 20, `0` off) caps the standalone sub-agents one user keeps deployed, failing closed when deployments cannot be counted.
- **Conversation search is no longer an existence oracle.** An agent-filtered search left the owner filter out of the query for everyone, so for a non-admin "matches only someone else's conversation" (rows rejected, empty) and "matches nobody's" (fallback to the unfiltered listing) answered differently — a substring oracle over other users' principal names and conversation ids. The owner scope is now pushed into the query for a caller who does not maintain that agent (`ConversationAccessGuard.maintainsAgent`); maintainers and admins behave as before.
- **Conversation review needs an authoring role under enforced workspaces too.** A team space grants `EDIT` to every member, so a chat-only `eddi-user`, viewer or approver in it could read other users' conversations with a review-enabled agent. `ConversationReviewPolicy.maintains` now requires `eddi-admin` or `eddi-editor` in both branches, and `EDIT` under enforcement.
- **LLM provider settings an editor may no longer author.** `LlmProviderAuthorPolicy` refuses, for non-admin callers, restricted providers (`eddi.llm.restricted-providers`, default `bedrock,gemini-vertex,oracle-genai,jlama`; `eddi.llm.restricted-embedding-providers`, default `bedrock,vertex`), Jlama `modelCachePath` / `workingDirectory` outside `eddi.llm.jlama.model-dir` (any, when unset), and content logging (`eddi.llm.content-logging.editors-allowed`, default `false`) — unless the replaced version already had exactly that setting. Applied on REST create/update/patch/duplicate of LLM, RAG, agent and group configs and on import and upgrade direct creates; `JlamaLanguageModelBuilder` confines paths to the base directory at build time for every config. See [Security](../security.md#llm-provider-settings-only-an-administrator-may-author).

- **Indirect provider names.** The task, cascade-step and judge `type` is expanded through `${vars:...}` at run time, so a variable or template in a provider field is refused from non-admin authors (carry-over still applies), `ProviderTypes` refuses at build time a type that reaches a restricted provider only through a variable, whoever authored it and whether or not authorization is enabled (the authoring checks apply only with `authorization.enabled=true`), and `create_sub_agent` refuses a model-chosen restricted provider other than the parent's own.

- **Review follow-ups.** One allowance now covers a new callee conversation's start turn and its message turn, and a skipped message on a continued conversation is not charged back. Spend charged back during a turn lowers that turn's allowance instead of raising its baseline. The standalone sub-agent cap fails closed when an agent's origin cannot be read, and an explicit end that cancels a running turn tears down the sub-agents that turn created from its live memory. In the authoring policy, a content-logging approval is bound to its task (`id`, or position), and cascade steps are judged on their effective provider and parameters (an untyped step inherits the task's type; every step inherits the task's parameters). A merge import refuses up front to replace a configuration it could not write back if a later step failed. A carry-over read for `version=0` resolves the current version first. Every carry-over fact is bound to the task and cascade step that sets it, and duplicate element ids carry nothing over. An element without an `id` (a task, a cascade step) is identified by its position and a digest of its content, so its privileged setting carries over only while it is unchanged; editing such an element needs an administrator. The end marks the conversation as ending before it signals the running turn, so a turn settling before `ENDED` is stored still tears down its sub-agents. In a cluster the cross-node cancel request carries an optional `reason: end`, so the node running the turn marks it as ended before cancelling it; a request without the field is a plain cancel, which is what an earlier node sends and how it reads the field. A turn the watchdog abandoned after an end signal still tears down its sub-agents when it later completes or fails, without storing its memory or writing any state. The end's cleanup no longer depends on the order of the end and the turn's finalization: besides the stored snapshot it tears down every deployed agent whose own `dynamicOrigin` names the conversation (and no discussion), scoped to the conversation's owner, and an ended conversation creates no sub-agent — one created while the end ran is torn down as soon as setup returns. A conversation confirmed gone (purged) counts as ended for this, so an agent whose setup outlived a purge is torn down too; a store that fails to answer tears nothing down. Final review round: task ids are URL-encoded in the policy's element paths, so an id cannot spell out another element's path; a `version=0` update resolves the version once for both the carry-over read and the write; a merge import checks restorability before every write of a resource, not only the first; the end cleanup skips its origin search when the conversation cannot be read (retention unknown); a failed or timed-out delegated start or message is charged what it recorded, and a timed-out one also holds the rest of its allowance for the turn; the per-user standalone cap reserves its slot atomically on the node (best-effort across nodes: with cap C and N nodes admitting at the same moment, up to C × N live agents). A delegation's allowance is now held from admission until it is settled, so parallel delegations of one turn cannot each be handed the same remaining money; every exit of `converse_with_agent` settles it, charging what the callee recorded (a start turn that spent before `say` failed included); a timed-out delegation keeps holding the original allowance minus everything charged, not the reduced message allowance. A sub-agent created with `retain: true` carries the flag in its own `dynamicOrigin`, so the end's origin search keeps it even when the creating turn was never stored. That flag is the single authority for both cleanup paths: `retain_agent` and `unretain_agent` write it on the agent at once (as well as in memory), and the snapshot path and the origin search both read the agent's current flag; an agent whose flag cannot be read is kept. The flag is tri-state: an agent created before it existed (absent) keeps the memory-based retention; a present flag always wins over the stored list. Admission reserves exactly the headroom left in one step (`SpendReservations.reserveHeadroom`), and an interrupted wait for a delegated turn is settled like a timeout. Teardown holds a per-agent lock (`SubAgentLocks`, per node) across reading the flag, undeploying and deleting; a `retain_agent` / `unretain_agent` meanwhile is refused with "the agent is being torn down" instead of reporting success. Delegation admission now runs wholly under the conversation's `SpendReservations` monitor: the recorded spend is read inside it, and the charge-back (`MemoryDelegationBudget.charge`) and every release take the same monitor, so neither a parallel admission nor a charge-back can land between the read and the hold; a conversation with no headroom (or no reservations to hold it in) is refused with an allowance of 0 instead of falling back to an unheld one. Retain and teardown are coordinated cluster-wide: `SubAgentLocks.acquire` takes the in-node lock and then the agent's lease `subagent.<agentId>` from `IConversationLeaseManager` (server-side TTL with heartbeat renewal on the cluster implementations, idempotent release; the local manager grants always, leaving the in-node lock as the guard). A retain or unretain that cannot get it within two seconds is refused with "changed elsewhere, try again"; a teardown that cannot get it skips that agent this time and logs it. The per-user cap stays best-effort across nodes.

### Design decisions

- The provider check is a scan of the document tree, like `CallerTokenAuthorPolicy`, so a provider counts wherever it is named (task, cascade step, judge, guardrail `provider`, summary, Dream, group settings, RAG embedding). For a restricted provider the carried-over "setting" is the provider plus every parameter whose name points it somewhere (model, region, profile, project, location, endpoint, credential, path), so prompt and temperature edits pass and re-pointing does not.
- Authoring is gated; stored documents keep working, with one exception at build time: a `type` that reaches a restricted provider only through `${vars:…}` is refused whoever saved it, since whoever controls the variable controls the provider.
- The remaining allowance handed down is the caller's ceiling less its recorded spend; what the calling task has spent and not yet recorded is not known to the tool, and the caller's tool loop catches it at its next round. A delegation that times out is charged what the callee had recorded when the caller gave up, and the rest of the allowance it handed down is held for the remainder of that caller turn, so the same money is not handed out twice in the turn. That hold is not persisted: spend the callee makes after the caller's turn has ended is not charged back to the caller's conversation (it is still metered to the tenant, and the callee stays held to the allowance passed down).

### Upgrade note

An administrator-authored LLM config whose `type` reaches `bedrock`, `gemini-vertex`, `oracle-genai` or `jlama` only through `${vars:…}` no longer builds; write the provider type literally. Editors can no longer create or re-point Bedrock, Vertex, OCI or Jlama configs (nor Bedrock/Vertex embeddings), set Jlama paths without a base directory, or turn content logging on; an editor's `setup_agent` is refused for those providers. A sub-agent without `allowedModels` is now limited to the parent's model. Standalone sub-agents now disappear when their conversation ends unless retained.
