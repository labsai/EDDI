## fix(postgres): U+0000 no longer loses data; one lock for lazy schema creation; strict datastore type (2026-11-18)

**Repo:** EDDI (`fix/postgres-nul-schema-and-type`)

### What changed and why

- **U+0000 on PostgreSQL (review E1, live P2).** PostgreSQL rejects the character in `TEXT` and `jsonb`; MongoDB stores it. One NUL in a user message lost the turn, user-memory writes, resources, a whole database-log batch and audit entries. Every PostgreSQL store now wraps its data source with `PostgresSanitizingDataSource` (a proxy at the JDBC boundary), which cleans each string as a statement binds it: U+0000 and unpaired surrogates become U+FFFD, in plain text and in JSON text (escaped `\u0000`, unpaired surrogate escapes), with escaped backslashes honoured. Lookups are cleaned the same way. The pgvector embedding store's connections are wrapped too: its text (`setString`) and its metadata when it is bound as `setObject(i, json, Types.OTHER)` with a JSON object or array (which is how langchain4j binds it, with no `::jsonb` cast in the SQL) are cleaned; metadata stored in any other layout is not covered by a test. Rules and the one-line adoption for a new store: [architecture](../architecture.md#differences-the-postgresql-boundary-hides).

- **One poisoned audit entry no longer takes its batch down (review M2, live: 45 entries undelivered).** `AuditLedgerService.appendIndividually` counted three refusals in a row as "store unavailable", handed every remaining entry to the retry-and-dead-letter path and, after three flushes, dead-lettered unrelated conversations with the poison one. It now classifies the failure (`AuditStoreFailures`: SQLState class 22/23, JSON/BSON errors, MongoDB document-rejecting codes): such an entry is dead-lettered alone with a `reason` and the rest is stored; everything else is an outage and backs off as before. The dead-letter file is written line by line with a lenient UTF-8 encoder (a lone surrogate used to throw `MalformedInputException` and lose the line and everything after it). For PostgreSQL the ledger makes an entry storable (U+0000 and unpaired surrogates to U+FFFD) before it is signed, so the stored row still verifies (`IAuditStore.replacesNulCharacter`). Not changed: `recordUndelivered` is still memory-only.

- **Lazy schema creation on a fresh database (review E2, live P1).** Each PostgreSQL store ran its own `CREATE TABLE IF NOT EXISTS` with no coordination: concurrent first requests raced (`pg_type_typname_nsp_index`), eleven stores swallowed the failure and went on without their table, and `PostgresAuditStore` ran `ALTER TABLE` (an `ACCESS EXCLUSIVE` lock) on every start. Every lazy creation now goes through `PostgresSchema.runOnce`: once per JVM and database, under an advisory lock shared by all nodes (one key per store), failures logged with their cause and thrown (retried by the next call). `PostgresAuditStore` alters only when the column or constraint is missing (`columnMissing`, `columnHasNotNull`). Behaviour change: the stores that swallowed now throw `IllegalStateException` from the first call when the schema cannot be created, which includes a database role without the right to run `CREATE TABLE IF NOT EXISTS` against tables that already exist (the connection stores used to log and carry on; the other 30 stores already failed there, so the role needs DDL rights either way). A future store adopts the helper by wrapping its DDL in `PostgresSchema.runOnce(dataSource, "<name>", stmt -> {...})`; the Agent Health stores (#1386-#1390) replace their `try (Connection ...; Statement ...)` block with it. No migration runner was built.

- **Strict datastore type (review E3, S1).** `eddi.datastore.type` selected MongoDB for every value but the exact string `postgres`, so `Postgres`, `postgresql` or a typo booted MongoDB against the built-in default URL, and the postgres-only compose stack read `EDDI_DATASTORE_TYPE` from a `.env` copied from `.env.example` (`mongodb`), which outranks the profile. A new `DatastoreType` is the one reader (`DataStoreProducers`, both V6 migrations, `PropertiesMigrationService`, `GridFsIndexInitializer`, `PostgresStartupSchemaLock`): trimmed, case-insensitive, `mongodb` / `postgres` / `postgresql` (alias), blank means the default, anything else throws. `DatastoreTypeGuard` runs first at startup and also refuses the `postgres` profile with a MongoDB type. `docker-compose.postgres-only.yml` now sets `EDDI_DATASTORE_TYPE: "postgres"` as a literal and `.env.example` says who reads the variable. Behaviour change for upgraders: a deployment whose type was misspelled used to run on MongoDB and now fails to start (the message names the accepted values); `Postgres` now means PostgreSQL. The Helm chart (not touched, chart version) stays stricter, which is allowed.

- **Parity defects confirmed in code (review E16, live P5).** `getActiveConversationCount(agentId, null)` threw a `NullPointerException` (now counts the rows without a version, as MongoDB's `eq(version, null)` does); `storeIfFieldEquals(resource, field, null)` bound `= NULL` and could never match, where MongoDB's `{field: null}` matches an absent field (now `IS NULL`); `eddi_schedules.name VARCHAR(512)` answered 500 for a 600-character name where MongoDB answers 201, and a client-chosen user, conversation or agent id longer than 255 characters failed a whole batch of database-log entries (now `TEXT`, altered once on an existing table). The U+0000 config case of P5 is the E1 fix. Confirmed but not changed: `sanitizeJsonPath` drops every character but letters, digits, `_` and `.` (a hyphenated field name addresses another field), Boolean filters treat an absent field as false, `TIMESTAMP` columns without a time zone are written in the JVM zone, and user-memory rows with a NULL agent are not unique by the index. Not changed: statement timeouts (out of scope).

### Design decisions

- **Replace with U+FFFD rather than remove.** Removal merges neighbours (`a<NUL>b` and `ab` become the same id) and shifts positions; the replacement character keeps both and is visible. It is not injective: `a<NUL>`, a literal `a�` and `a` plus an unpaired surrogate are stored as one value, so ids that differ only in such characters address one row.
- **Audit rows are made storable before they are signed.** The ledger signs what it stores (timestamps and payloads are already normalised first); a PostgreSQL row with U+0000 replaced after the HMAC would read back as tampered. `IAuditStore.replacesNulCharacter()` (true only for PostgreSQL) switches the replacement on, so MongoDB entries keep the character.
- **Classify the audit failure by what the store said, not by counting.** Rejected: a larger consecutive-failure limit (it only moves the poison threshold) and treating every exception as an outage (the old behaviour). An exception nobody classified still counts as an outage, so an unknown failure mode backs off instead of dead-lettering.
- **Advisory lock keys per step, in a range distinct from the startup lock.** Reusing the startup key would make a store creating its schema during startup wait for its own JVM. Rejected: a JVM-wide monitor only (does not help replicas) and retrying on SQLSTATE 23505/42P07 (hides the failure and still races).
- **Strict datastore type refuses the `postgres` profile with a MongoDB type** (the S1 trap) instead of only fixing the compose file, because a copied `.env` can reach the same combination through any other launcher.
- **One boundary instead of 900 call sites.** `setString`/`setObject` are called some 900 times across the stores; a proxy over the data source covers all of them and every future store. JSON parameters are recognised by the `::jsonb` cast in the SQL or a `PGobject` of type json/jsonb.

### Review round

- **`lock_timeout` is restored** (it was left at 0 on the pooled connection, and 0 during the DDL itself): the session's value is read first and put back in `finally`; the bounded timeout (60 s) stays in force during the DDL, so an `ALTER TABLE` behind a long query fails cleanly instead of stalling the table.
- **Audit text is made storable after normalisation** (so a POJO, array, set or `JsonNode` payload value is already a map, list or string) and includes the conversation id; a unit test signs, applies the PostgreSQL replacement and verifies, and `AuditNulSigningPostgresIT` does it against a real database.
- **`PostgresText.json` allocates only at the first position that needs replacing**; typical Jackson output (quotes, newlines, emoji) is returned as the same instance.
- **pgvector metadata**: a `setObject(i, string, Types.OTHER)` whose value starts with `{` or `[` is cleaned as JSON text.
- **SQL parser**: pgjdbc's `??` is one literal `?`; `E'...'` strings and dollar-quoted bodies are skipped. Parse results are cached in a bounded Caffeine cache (eviction), and `Instance.get()` no longer takes a lock.
- **Schema steps back off and use per-store lock keys**; `widenToText` is best effort (a view over the column no longer fails the store; one WARN). The key is derived from the step name up to a colon, so the collections of `PostgresResourceStorage` share the lock of their one table.
- **Lookups use the same replacement as stored values**: `toContainmentJsonPath` cleans its value (reference lookups still match a stored `U+FFFD`).
- **Explicit JSON helper at the bind site** for the four highest-volume writers (conversation memory, resource storage, user memory, audit): their JSON text passes through `PostgresText.json`, so JSON-ness is known by type there and the proxy's SQL inference is the fallback. The other 37 stores rely on the proxy.
- `DeploymentManifestsTest` again ties the chart's list of datastore types to what `DatastoreType` accepts; the stale comment in `ci.yml` is corrected. `helm/eddi/templates/configmap.yaml` and `helm/eddi/values.yaml` still describe the old exact comparison in comments; they are not edited here (a chart change needs a chart version bump, open PR #1400).

### What is left

- The versioned migration runner (the lambdas passed to `PostgresSchema.runOnce` are what it replaces), statement timeouts and indexes (E15) are untouched.
- `AuditLedgerService.recordUndelivered` is memory-only: after a restart an `INCOMPLETE` chain reads `BROKEN` unless the dead-letter file is consulted.
- The other `VARCHAR(255)` columns and the E16 items listed above.
- `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` still runs unconditionally in the other stores' lazy creation (only `PostgresAuditStore` asks the catalogue first); `PostgresSchema.columnMissing` is the tool to move them over.
