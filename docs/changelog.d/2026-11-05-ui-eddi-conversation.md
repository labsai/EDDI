## 💬 feat(ui): `@eddi/conversation` — the agent kind (2026-11-05)

**Repo:** EDDI (`feat/ui-eddi-conversation`, stacked on `feat/ui-eddi-ui`)

Phase 3b of the frontend unification plan (`planning/frontend-unification-plan.md` §1.3, §2.5, §3.1, §3.2, §7 phase 3, D9): the third shared package, [`@eddi/conversation`](../../ui/packages/conversation/README.md), with the `AgentConversation` controller.

### What changed and why

- **`AgentConversation`** ([`agent-conversation.ts`](../../ui/packages/conversation/src/controller/agent-conversation.ts)) — the 1:1 turn state machine, framework-free (`subscribe` / `getSnapshot`, read through `useSyncExternalStore`), on `@eddi/core`: streaming, a 409 that restores the draft, dropped vs paused turns, `inputField` on `done`, undo/redo, rerun, stop, cancel, the refresh after a pause, and `resume(conversationId)`, which restores the last output's quick replies. Its suite is the union of the 1:1 loops' turn rules, without React.
- **The shared `conversation.*` strings** in the eleven locales; the Manager's `i18n:check` reads a package's own locale files with the app's.
- **The shared components** — `Message`, `MessageList`, `Composer`, `SecretInput`, `QuickReplies`, `ThinkingIndicator` / `TypingIndicator`, `PausedCard`, `RatingCard`, `StepRating`, `ScrollToBottom` — moved from the widget with their history, and **the one markdown renderer** (`MarkdownContent`, §2.5): images in model text as links, raw HTML only through rehype-sanitize (parser lazy, still rendered for every agent until D9's setting), KaTeX (`trust: false`) and highlight.js lazy. GFM is now parsed without its serialiser ([`remark-gfm-parse.ts`](../../ui/packages/conversation/src/markdown/remark-gfm-parse.ts)): remark-gfm also registered mdast-util-to-markdown and markdown-table, which a renderer never calls — about 4 KB of gzip off every first load that renders markdown; a test renders a corpus both ways and compares.
- **The widget (`ui/chat`) on the controller.** `ChatProvider` owns one `AgentConversation` and keeps the widget's own state beside it (config, agent name, review notice, rating profile); `useChatState()` / `useChatDispatch()` are unchanged for components. `ChatWidget` keeps the embedding — route, `?token=`/postMessage auth, URL colours, `hide*` flags, the profile gate, ratings, HITL polling — and hands the route to the controller as a transport (conversation, managed, or the demo's `createDemoTransport`). Deleted: `turn-notices.ts`, `api/hitl-api.ts`, `ime.ts` (now in the package). The component tests stay in the widget and import from `@eddi/conversation`; `chat-store.test.tsx` and every `ChatWidget.*` suite pass unmodified. The 108 moved strings left `src/i18n/locales` for the package's (`conversation.` prefix, same translations). Visible changes: none intended; a guardrail notice is now recorded on the reply it explains (the widget does not render it yet). First load 167.7 KB gz (was 169.3; budget 170).
- **The Manager's chat bubble on the one renderer.** `chat-message.tsx` — the Chat page, Agent Studio, the test drawer and Workforce chat — renders replies through `MarkdownContent` ([`conversation-markdown.tsx`](../../ui/manager/src/components/chat/conversation-markdown.tsx), with the Manager's `t` for the shared strings, which `i18n/config.ts` now merges in). Visible: KaTeX for `$$…$$`, highlighted fenced code with a copy button, links in a new tab, and raw HTML rendered **sanitised** instead of shown as escaped text (D9: every agent until the per-agent setting). `@eddi/conversation/markdown.css` styles the copy button, tables and highlight tokens from the shared tokens. The feature matrix's KaTeX and highlight cells for `chat-panel` are now assertions (an MSW reply with math and code, `RICH_MARKDOWN_TRIGGER`).
- **Quick replies on resume (Manager).** A conversation reopened from history, or resumed on opening an agent, now offers the last reply's quick replies again (`installSnapshot`, `use-chat-load-pause.test.tsx`) — the same rule as `AgentConversation.resume`, kept in `use-chat.ts` until `ChatPanel` moves onto the controller. Mutation-checked: without the line, the new test fails.
- **Widget RTL e2e.** [`chat-widget-rtl.fullstack.spec.ts`](../../ui/manager/e2e/fullstack/chat-widget-rtl.fullstack.spec.ts) opens `/chat/demo/showcase?lang=ar` against the real server (the only tier that serves `/chat`) and checks `dir="rtl"` and the mirrored composer and message layout.
- **Gates.** CI's `UI Chat` job runs the package's type check, lint and tests; `sharedPackage({ routerFree: true })` and `boundaries.test.ts` keep it router-free, off `window.__EDDI_*__`, and unimported by `@eddi/core` and `@eddi/ui`; `AutoApproveCopilotPolicyTest` covers its config files.
- **Archived changelog links.** Nine links in `docs/changelog/2026-09.md`, `2026-10.md` and the phase-0 fragment named widget components this change moves; they now point at the package files (`DocumentationLinksTest`). Only the link targets changed.
- **Platform Operator.** No endpoint, field, default or failure mode changed, and the operator's own chat is untouched (phase 6), so neither its prompt nor its allow-list changed and `operator-revision.json` was not bumped. No Stryker-scoped file changed.

### Not done

- **`ChatPanel` (`use-chat.ts`), the test drawer, Workforce chat and the Workforce member thread are not on `AgentConversation` yet.** The Manager loop differs from the widget's in ways each of its 30 suites pins (error bubbles and toasts where the widget writes notices, the conversation epoch and detached-stream grace, the load guard, following an executing turn, debug events, agent selection); moving it is a step of its own. They share the renderer and the resume rule only. The Operator stays on its own code (phase 6).
- `Message` does not render a sent message's attachments or a reply's guardrail notes yet (the widget never had them; the Manager's bubble still does), and `ActivityIndicator` has no guardrail state. `MessageList` is not windowed (sticky scroll only).
- The §2.5 test that fails on a `ReactMarkdown` import bypassing the shared renderer is not written: thirteen Manager files (groups, Workforce, the Operator, update check) still use their own.
- Feature matrix: `output-images` stays unsupported on the chat panel (the Manager's bubble renders text parts only); the widget's `history` and `inline-hitl` cells are unchanged by design.
