## 💬 feat(ui): `@eddi/conversation` — the agent kind (2026-11-05)

**Repo:** EDDI (`feat/ui-eddi-conversation`, stacked on `feat/ui-eddi-ui`)

Phase 3b of the frontend unification plan (`planning/frontend-unification-plan.md` §1.3, §2.5, §3.1, §3.2, §7 phase 3, D9): the third shared package, [`@eddi/conversation`](../../ui/packages/conversation/README.md), with the `AgentConversation` controller.

### What changed and why

- **`AgentConversation`** ([`agent-conversation.ts`](../../ui/packages/conversation/src/controller/agent-conversation.ts)) — the 1:1 turn state machine, framework-free (`subscribe` / `getSnapshot`, read through `useSyncExternalStore`), on `@eddi/core`: streaming, a 409 that restores the draft, dropped vs paused turns, `inputField` on `done`, undo/redo, rerun, stop, cancel, the refresh after a pause, and `resume(conversationId)`, which restores the last output's quick replies. Its suite is the union of the 1:1 loops' turn rules, without React.
- **The shared `conversation.*` strings** in the eleven locales; the Manager's `i18n:check` reads a package's own locale files with the app's.
- **The shared components** — `Message`, `MessageList`, `Composer`, `SecretInput`, `QuickReplies`, `ThinkingIndicator` / `TypingIndicator`, `PausedCard`, `RatingCard`, `StepRating`, `ScrollToBottom` — moved from the widget with their history, and **the one markdown renderer** (`MarkdownContent`, §2.5): images in model text as links, raw HTML only through rehype-sanitize (parser lazy, still rendered for every agent until D9's setting), KaTeX (`trust: false`) and highlight.js lazy. GFM is now parsed without its serialiser ([`remark-gfm-parse.ts`](../../ui/packages/conversation/src/markdown/remark-gfm-parse.ts)): remark-gfm also registered mdast-util-to-markdown and markdown-table, which a renderer never calls — about 4 KB of gzip off every first load that renders markdown; a test renders a corpus both ways and compares.
- **The widget (`ui/chat`) on the controller.** `ChatProvider` owns one `AgentConversation` and keeps the widget's own state beside it (config, agent name, review notice, rating profile); `useChatState()` / `useChatDispatch()` are unchanged for components. `ChatWidget` keeps the embedding — route, `?token=`/postMessage auth, URL colours, `hide*` flags, the profile gate, ratings, HITL polling — and hands the route to the controller as a transport (conversation, managed, or the demo's `createDemoTransport`). Deleted: `turn-notices.ts`, `api/hitl-api.ts`, `ime.ts` (now in the package). The component tests stay in the widget and import from `@eddi/conversation`; `chat-store.test.tsx` and every `ChatWidget.*` suite pass unmodified. The 108 moved strings left `src/i18n/locales` for the package's (`conversation.` prefix, same translations). Visible changes: none intended; a guardrail notice is now recorded on the reply it explains (the widget does not render it yet). First load 167.7 KB gz (was 169.3; budget 170).
- **Gates.** CI's `UI Chat` job runs the package's type check, lint and tests; `sharedPackage({ routerFree: true })` and `boundaries.test.ts` keep it router-free, off `window.__EDDI_*__`, and unimported by `@eddi/core` and `@eddi/ui`; `AutoApproveCopilotPolicyTest` covers its config files.
