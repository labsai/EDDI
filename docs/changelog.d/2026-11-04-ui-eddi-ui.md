## 🎨 feat(ui): `@eddi/ui`, and both apps on its tokens, theme and i18n (2026-11-04)

**Repo:** EDDI (`feat/ui-eddi-ui`, stacked on `refactor/ui-eddi-core`)

Phase 3a of the frontend unification plan (`planning/frontend-unification-plan.md` §3.1, §3.3, §7 phase 3, D3): the second shared package, `@eddi/ui` under [`ui/packages/ui`](../../ui/packages/ui/README.md), with the Manager and the Chat UI moved onto its foundations. Phase 3 is split: 3b builds `@eddi/conversation` (`AgentConversation` and the shared chat components) on top of this.

### What changed and why

- **`@eddi/ui`** — consumed as source like `@eddi/core` (`exports` → `src/`), React allowed, no API calls:
  - **Tokens** (`@eddi/ui/theme.css`): the Manager's Tailwind v4 `@theme` — semantic colours, the `brand-*` / `warn-*` / `ochre-*` scales, radius, font stack, light and `.dark` — moved verbatim out of `ui/manager/src/index.css`, which now imports it. Plain `@theme`, not `inline`, so `/branding/brand.css` still reaches the utilities. `@source "../"` lets Tailwind see the package's classes. `BrandDeliveryTest`, `brand-css.test.ts` and `no-hardcoded-amber.test.ts` read the new file.
  - **`--chat-*` as documented aliases** (`CHAT_TOKEN_ALIASES`, `SEMANTIC_TOKENS`). Fifteen of the widget's variables are now `var(<shared token>)` (`--chat-bg` → `--color-background`, `--chat-accent` → `--color-primary`, `--chat-user-bg` → `--chat-accent`, …); the widget gives the tokens its own palette per theme, so nothing renders differently. The names, the URL colour parameters and `brand.css`'s `--chat-accent` keep working because an override of the `--chat-*` name still wins. [`chat-aliases.test.ts`](../../ui/chat/src/styles/chat-aliases.test.ts) pins `variables.css` to the table, every one of the 31 names to the colour it had before (both themes), every name a colour parameter writes, and `--chat-accent` staying overridable by `brand.css`.
  - **Theme**: `ThemeProvider` / `useTheme` (moved from the Manager; marks `<html>` with a class or with `data-theme`) and the helpers under it (guarded storage, resolve, apply, an OS-change subscription that re-reads the preference). The widget's `useTheme` keeps its own `?theme=` precedence on top of the helpers.
  - **i18n**: `setupI18n` — English bundled, every other locale its own chunk and only the active one loaded (`partialBundledLanguages` + a lazy backend over a loader map), region tags matched, `{{productName}}` default variables, `dir`/`lang` from the RESOLVED language; `setDefaultVariables` for a brand saved at runtime; `SUPPORTED_LANGUAGES` (the eleven), `RTL_LANGUAGES`, `matchLanguage`. The Manager's `i18n/config.ts` is now its locale loaders plus one `setupI18n` call.
  - **Per-locale fonts**: phase 0's `locale-fonts.ts` moved in as the separate entry `@eddi/ui/fonts`. Separate on purpose: re-exported from the main entry, it made the widget's build emit all 468 Noto font files into `chat/dist` although nothing called it.
  - **Primitives**: `Button` / `buttonVariants` (and `cn`) and the theme-following, direction-aware `ThemedToaster` (it takes `rtl` as a prop; the Manager's new `AppToaster` passes it). The 174 Manager files that imported `@/components/ui/button` or `@/components/layout/theme-provider` import from `@eddi/ui`; `lib/utils.ts` re-exports `cn`.
  - **Boundaries**: `sharedPackage({ react, noApi })` in [`ui/eslint.config.base.js`](../../ui/eslint.config.base.js) lints `.tsx` with the hook rules and forbids `@eddi/core`, `fetch`/`XMLHttpRequest`/`EventSource`/`WebSocket` and `window.__EDDI_*__` in `@eddi/ui`; [`boundaries.test.ts`](../../ui/packages/core/src/boundaries.test.ts) checks the same (and still that core imports no UI package, and no cycle).
- **Widget i18n**: the Chat UI's own `t()` and four string tables became i18next bundles in [`ui/chat/src/i18n/locales`](../../ui/chat/src/i18n/locales/en.json), set up through `setupI18n` without react-i18next (the locale is chosen once; `main.tsx` awaits `initLocale` before the first render, so `t()` still works outside React). The seven new locales — `ar`, `zh`, `th`, `ja`, `ko`, `pt`, `hi` — are translated with the Manager's terminology for agent, conversation, approval and rating. Placeholders moved from `{name}` to `{{name}}`; a missing value still stays visible, and a value is never interpolated twice. `?lang=ar` lays the widget out right to left. [`i18n.test.ts`](../../ui/chat/src/i18n/i18n.test.ts) checks all eleven files for parity, placeholders and real translation, and every key the code passes to `t()`.
- **Gates**: CI's `UI Chat` job runs `@eddi/ui`'s type check, lint and tests next to `@eddi/core`'s. `i18n:check` already walks `ui/packages/*/src`; the package has no `t()` keys of its own (a primitive takes its text as a prop). `AutoApproveCopilotPolicyTest` covers the new package's config files. The seven script-font packages moved from the Manager's dependencies to the package's; `ui/package-lock.json` was regenerated in a `node:26.13.0` container.
- **Docs**: the three AGENTS.md files, the packages README, the new package README, the Chat UI README (eleven languages, the token layers) and [`chat-ui-embedding.md`](../chat-ui-embedding.md) (`lang`, the aliases). Two links to moved files were repointed (`docs/changelog/2026-10.md`, the phase-0 fragment) for `DocumentationLinksTest`.
- **Platform Operator**: no endpoint, config field, default or failure mode changed; neither its prompt nor its allow-list needed an update, so no revision bump. Stryker's scope (`lib/operator/**`, `updates.ts`, `hitl-tool-approvals.ts`) has no moved file. No API change, so no MSW handler changed.

### Behaviour and visual changes

- **Widget**: speaks eleven languages instead of four; its first load grew from 162.2 to 169.1 KB gz (budget 170) — i18next, less the three string tables that left the entry chunk. Each locale is a 2.8–3.4 KB gz chunk. `chat/dist` gains those ten files.
- **Manager**: none intended. The tokens, button and toaster were moved, not edited: the same declarations, classes and props (the main stylesheet's size is in the table below). A stored theme value that is not `dark`/`light`/`system` is now ignored instead of trusted.

### Moved and deferred

- **Moved to `@eddi/ui`**: tokens, theme provider, i18n setup, locale fonts, `Button`, `ThemedToaster`, `cn`.
- **Not moved**: the Manager has no tooltip or icon-button component to move (icon buttons are `Button size="icon"`; tooltips are Radix used in place), and its dialogs, badges and inputs are not needed by the 3b chat components from both apps. The widget is not restyled onto Tailwind: its BEM stylesheet reads the shared tokens through the aliases, which is what 3a needs; D3's move to Tailwind comes with the shared components in 3b. The widget keeps the Noto Sans faces `chat.html` declares rather than loading script fonts per locale.
- **3b**: `@eddi/conversation` with `AgentConversation`, `MessageList`, `Message`, `Composer` and the rest, and the `conversation.*` namespace.
