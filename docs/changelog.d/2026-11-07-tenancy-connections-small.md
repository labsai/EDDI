## 🐛 fix(tenancy,connections): agent quota outage pre-registered, authorize needs a per-user connection, UTC grant timestamps (2026-11-07)

**Repo:** EDDI (`fix/tenancy-connections-small`)

### What changed and why

- **The first agent-count outage now fires `EddiQuotaStoreUnavailable`.** `TenantQuotaService` registers `eddi.tenant.quota.unavailable` at 0 for the default tenant so that Prometheus' `increase()` sees the first refusal. The list it registered held `conversation`, `api_call` and `cost` but not `agent`, which the deploy gate also records, so that series was born at 1 and the first agent-count outage, the case the pre-registration exists for, never alerted. `agent` is now on the list ([`TenantQuotaService`](../../src/main/java/ai/labs/eddi/engine/tenancy/TenantQuotaService.java)).
- **`POST /connections/{name}/authorize` refuses a connection that cannot take a per-user grant.** It checked only `authType == OAUTH2_AUTHORIZATION_CODE`, while the callback also requires `binding: PER_USER` and refuses before redeeming the code. Since 6.4.0 a write cannot store that combination, but validation runs only on the write path, so a connection saved earlier with the default `SERVICE` binding still loads: the user went through the provider's consent screen and came back to `?error=exchange_failed`. `authorize` now answers **400** naming the binding and the fix, and issues no state and no cookie ([`RestConnectionAuthorization`](../../src/main/java/ai/labs/eddi/connections/rest/RestConnectionAuthorization.java), [`connections.md`](../connections.md#per-user-accounts)).
- **PostgreSQL grant and OAuth-state timestamps are UTC wall clocks.** The columns are `TIMESTAMP` without time zone. `refresh_lease_expires_at` was already written and read as UTC. `expires_at`, `created_at`, `updated_at` and `last_refresh_at` in `connection_grants`, and `created_at`, `expires_at` and `consumed_at` in `connection_oauth_states`, went through the JDBC driver's default, the JVM's zone, and the SQL stamps used `CURRENT_TIMESTAMP`, which a `TIMESTAMP` column takes in the session's zone, also set from the JVM. Replicas in different zones therefore moved every access-token expiry by their offset (a refresh hours early, or a dead token served as live), and in a daylight-saving zone the repeated autumn hour could put a ten-minute OAuth state's expiry before its creation, so `claim()` refused a valid callback. Every bind and read now goes through the new [`PostgresTimestamps`](../../src/main/java/ai/labs/eddi/datastore/postgres/PostgresTimestamps.java) with a UTC `Calendar`, and every SQL stamp is `(CURRENT_TIMESTAMP AT TIME ZONE 'UTC')`. The grant insert now names `created_at`, because an existing table keeps its old column default.
- **Hygiene.** `TurnCostMeter` takes `SpendSinks` as a constructor argument instead of a field that tests left null and the code null-checked; tests pass `SpendSinks.NONE`. `ResourceAccessGuard.callerIsAdmin()` duplicated `isAdmin()` and is removed; its two callers use `isAdmin()`.

### Upgrade note

On a PostgreSQL deployment whose JVM did **not** run in UTC (the container image does unless `TZ` is set), the existing grant rows hold local wall clocks. They are now read as UTC, so each grant's `expires_at` is off by the zone's offset until its next refresh rewrites it. East of UTC an expired access token can be presented for up to that many hours and the provider rejects it; unlinking and relinking the account clears it at once. West of UTC the token is refreshed early, which is harmless. OAuth states live ten minutes, so only a link in progress during the upgrade is affected, and the user starts it again. MongoDB stores instants and is not affected.

### Design decisions

- **A UTC `Calendar` rather than migrating the columns to `TIMESTAMPTZ`.** `TIMESTAMPTZ` is the cleaner type, but the change is an `ALTER COLUMN ... TYPE` in `createSchema()`, which rewrites the table under an exclusive lock on every replica that boots, and converts existing rows through whichever zone that replica runs in. The lease column had already settled on the UTC wall clock; one rule for the whole table is easier to keep right than two.
- **One helper, in `datastore/postgres`.** Other PostgreSQL stores write `TIMESTAMP` columns the same way. They are out of scope here; the helper is where they would go.
