## fix(configs): save-time validation, in-use delete guards, fail-closed import, whole-or-nothing export, deployment failure reason (2026-11-18)

**Repo:** EDDI (`fix/config-validation-import-and-delete-guards`)

### What changed and why

Findings E4-E9 and F5 of the November 2026 code review (live: L5, L11, I1, I2, OI4), then a fix round answering the branch's independent review (M1-M6, S1-S9).

**Import must not produce a hollow agent silently (E6, E7, E8; I1, I2).** A `strategy=create` import (and the first promotion of `…/sync`, single or batch) whose workflow names a configuration the archive does not contain used to drop the step, log a WARN and answer 201 — an agent that deploys `READY` and cannot answer. It is now refused with `422` listing every missing reference; the archive's workflows are scanned before the first write, so nothing is written and nothing has to be rolled back. `allowIncomplete=true` (a query parameter, and a `SyncRequest` field for batch sync) imports it anyway. A 201 with findings carries `X-Import-Warnings` and a JSON body (`resourceUri`, `warnings`, `dropped`); `UpgradeResult.warnings` carries the same for upgrade and sync. Missing `${vault:…}` secrets are reported only to administrators, the role that may read secret metadata. Two same-name snippet files in one archive no longer create two snippets, and a created RAG config's schedules are removed when the import rolls back. Files: `RestImportService`, `IRestImportService`, `UpgradeExecutor`, `SyncRequest`, `ImportVaultReferences`.

**Save-time validation (E4; L11).** `LlmConfigSaveValidator` and `WorkflowConfigSaveValidator`, called by `LlmStore` / `WorkflowStore`, refuse only what fails at run time; each rule names the runtime code that fails on it. LLM: a task type no builder exists for (when no cascade is configured), a cascade step whose own or inherited type is blank or unknown, a step `timeoutMs <= 0`, a numeric parameter outside the range `model-parameters.json` declares (or NaN), `retry.maxAttempts < 1`, and the deploy-time cascade and self-hosted endpoint errors. Not checked any more, because the runtime copes: a cascade step without a type (it inherits the task's), a blank model key, a parameter that does not parse, negative backoff values, the judge model. Workflow: a step without a type, an `eddi:` type without a registered host, and a missing or malformed `config.uri` for the steps whose task cannot configure without one (behavior/rules, httpcalls/apicalls, llm/langchain, mcpcalls, rag); a context-only `ai.labs.output` step without a uri is valid again, and the uri is trimmed as the runtime trims it.

**One leniency mechanism (M1, M2, M3).** `ConfigValidationPolicy` is gone; the marker is `ai.labs.eddi.configs.LenientConfigWrite` (a `ScopedValue`, byte for byte the class `fix/pipeline-trust-and-robustness` adds). Inside it the validators only log; outside they throw (400). The rule for the series:
- *strict*: REST create/update/patch, MCP `create_resource`/`update_resource`, the cascade-save (`AgentCascadeService`, MCP `apply_agent_changes`);
- *lenient, in process*: import (create, merge and the rollback compensations), sync and upgrade, every duplicate endpoint (the agent deep copy reaches the REST beans in process), and the API-agent re-sync's rewrite of the stored LLM config and workflow, which now writes through the in-process REST beans inside the marker rather than its loopback HTTP client;
- *valid by construction*: agent setup (`/agentsetup`, MCP `setup_agent`/`create_api_agent`, the Operator bootstrap) writes through loopback HTTP clients the thread-bound marker cannot reach; a test proves everything it generates passes the strict checks.
No request header or parameter makes a save lenient. Warnings shown to the caller are collected explicitly before each write (`problems(...)`), not through the marker. `ConfigWritePathPolicyTest` holds the write-path table and fails when a new class writes LLM configs or workflows without being classified; `ConfigSaveValidatorRegressionNetTest` sweeps `docs/agent-configs/`, every LLM or workflow JSON example in `docs/`, and the setup wizard's output through the strict checks.

**In-use guards on delete (E5; L5, OI4).** `ResourceInUseGuard`, called from `RestVersionInfo.delete`: deleting a workflow or configuration version that something uses answers `409` (`RESOURCE_IN_USE`) unless `force=true`, now a declared query parameter of every guarded delete endpoint (workflow, LLM, behavior, httpcalls, mcpcalls, output, property, dictionary, rag, parser). "Uses" covers what a deployment pins: a workflow version an older, deployed agent version lists, and a config an older workflow version names that a current or deployed agent version lists (S2). The lookups are id-only reverse queries (new `IResourceStorage.find…ContainingAny`, one `$in` / one OR-ed `@?` jsonpath query per 50 URIs on the existing indexes) plus one read of the deployment records; descriptors are read only to name users (S6). Counts and names cover only what the caller may view, with a yes/no `othersNotListed` (S4). A lookup that fails refuses with `503 IN_USE_CHECK_FAILED` instead of deleting unguarded. Deleting a deployed agent with active conversations answers `409` (`AGENT_HAS_OPEN_CONVERSATIONS`) unless the declared query parameter `endAllActiveConversations=true`; the conversations are counted first and ended only after every check that can still refuse has passed (M6), page by page, with the new end reason `agent-deleted`. The guard is constructor-injected into `RestAgentStore`; the cascade bypass is a `ScopedValue` (`callUnguarded`); MCP passes `force` / `endAllActiveConversations` as arguments.

**Export is whole-or-nothing (E9).** An export that cannot serialize or write a configuration, the snippets or the schedules fails (`500`; `422` naming the resource when a stored configuration cannot be serialized) instead of producing an archive that looks complete. A configuration whose descriptor row is missing is exported without it, as before (S7).

**Deployment failure reason (F5), part.** A failed deployment carries a reason code from a closed set (`VAULT_GRANT_MISSING`, `STEP_TYPE_UNKNOWN`, `CONFIG_INVALID`, `REFERENCE_MISSING`, `DEPLOYMENT_FAILED`), classified by the most specific cause in the chain, returned by default as `failure: {code, message}` to everyone who may use the agent, and counted in `eddi.deployment.failed{reason}`.

### Design decisions

- Pinned deployments, not only current versions, protect a resource; the cost stays a constant number of indexed queries per delete. Rejected: reading every deployed agent's configuration (cost grows with deployments).
- A failed in-use lookup refuses (503, retryable, `force=true` as the explicit way past it): the delete is irreversible and the check is what stands between it and an agent that stops working. Rejected: proceeding with a WARN.
- Conversations paused for a human (`AWAITING_HUMAN`) are neither counted nor ended by an agent delete — the rule undeploy and old-version cleanup follow — so a forgotten approval cannot block a delete and a pending human decision is not destroyed as a side effect.
- `importAgent` / `executeSync` gained `allowIncomplete` on the JAX-RS method itself (an overload cannot add a query parameter); the previous signatures stay as default methods.

### Behaviour changes an upgrader will notice

- `strategy=create` imports of archives that name missing configurations answer 422 (add `allowIncomplete=true` for the old behaviour).
- Saving an LLM config or workflow that cannot run is a 400; what the runtime tolerates is accepted as before.
- Deleting a used workflow/config (including one only a deployed older version uses) is a 409; a deployed agent with active conversations is a 409; a store that cannot answer the check is a 503.
- A failed export is a 500 (422 for a configuration that cannot be serialized) instead of a smaller archive.
- **The Manager must ship the UI follow-up together with this branch**: `deleteGroupWithMembers` deletes deployed member agents and must pass `endAllActiveConversations=true` (or ask), or a member with active conversations is reported as "could not be deleted" forever.

### What is left

A deployment made with `autoDeploy=false` is not recorded and so does not pin resources for the in-use guard.
