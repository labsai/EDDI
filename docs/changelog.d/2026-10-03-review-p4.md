## 🐛 fix(hitl,schedule): review follow-ups — ABORT and human-turn timeouts survive, legacy store path guarded, pre-upgrade schedules not disabled (2026-10-03)

**Repo:** EDDI (`review/p4`, on `fix/hitl-scheduling`)

### What changed and why

**Every HITL timeout is re-armed, not only approve/reject.** The retry-later handling covered `AUTO_APPROVE`/`AUTO_REJECT`; an `ABORT` whose cancel failed, and an expired human turn (`SKIP_TURN`) whose skip failed, still logged the failure and completed the fire, so a finite policy became wait-forever on a store blip. `HitlTimeoutHandler` now treats all of them alike — retried while the pause is still waiting, done once it is not — and `GroupHitlCoordinator.skipHumanTurnOnTimeout` no longer swallows its own failure (the handler could never see it).

**The v5 LLM-store path no longer slips past `SelfUngatingGuard`.** `/langchainstore/langchains` is rewritten onto `/llmstore/llms` by `LegacyPathRewriteFilter` before routing, so an approved write through the old spelling carrying `toolApprovals` was not recognised. Both spellings are guarded; a call whose request cannot be resolved (an MCP tool aimed at this server) is refused on the bare `toolApprovals` key.

**Schedules created before the creator snapshot are not disabled on their first fire.** The USE re-check ran against an empty team set for a row that has no snapshot, which would have disabled every team-shared and administrator-created schedule after an upgrade with workspaces enforced. A row with no snapshot (`creatorTeams` absent) is now left alone; Postgres stores an empty team list as `[]` so "no teams" stays distinct from "no snapshot".

**Docs:** [`scheduling.md`](../scheduling.md) says what happens to schedules an older release disabled on undeploy (they carry no `disabledReason`; enable them once by hand), [`hitl.md`](../hitl.md) the wider retry scope.
