## Workforce as its own app — frontend unification phase 5 (2026-11-05)

**Repo:** EDDI · **Branch:** `feat/workforce-app` (stacked on `feat/workforce-sidebar-home`, PR #1284)

Phase 5 of the frontend unification plan (`planning/frontend-unification-plan.md`, §3.1, §4.1, §4.2, §7): Workforce leaves the Manager's bundle and becomes `ui/workforce`, an app of its own beside `ui/manager` and `ui/chat`, with its own `workforce.html`, `main.tsx`, router, i18n, tests and E2E suite. It loads only what it uses.

**What changed**

- **`ui/workforce`** — `src/app.tsx` holds the `/workforce/**` routes the Manager's `app.tsx` used to; `src/main.tsx` boots through `startApp`. The Workforce components, pages, hooks and libs moved here with `git mv` (64 modules, 55 test files), so `git log --follow` traces them. Dev server on port 3002, MSW `ui` E2E tier (`playwright.config.ts`), its own Vitest config, ESLint, tsconfigs, `AGENTS.md` and `CLAUDE.md`.
- **`@eddi/app-kit` (`ui/packages/app-kit`)** — a fourth shared package: the layer the two signed-in apps share. Workforce rendered some two hundred Manager modules (the API client and hooks, the Keycloak session, the UI primitives, the group, chat and editor components, the mock API); they moved here at the paths they had, imported as `@eddi/app-kit/<path>`. Also new in it: `startApp` and `AppProviders` (both apps boot and wrap the same way), `setupAppI18n` (each app's strings deep-merged with the package's and `@eddi/conversation`'s), `styles/app.css` (the base stylesheet, with `@source`), and `AppLink` / `AppNavigate` / `useAppNavigate` over `lib/app-paths.ts`.
- **Moving between the apps is a page load.** A `<Link>` from one router to the other app's path matches nothing, so every cross-app link (the welcome chooser's Workforce card and its `eddi-user` redirect, the mode switcher, Workforce's links into the Manager, the Operator link, the pause notice's review link) goes through `AppLink` / `AppNavigate` / `useAppNavigate`, which keep the router inside the app. Theme, language, pins and the Keycloak session carry over through same-origin storage (keys unchanged).
- **The Manager loses the Workforce routes**, the `workforce.html` build input, `workforce-pins` (now `@eddi/app-kit`, since the Manager's sign-out clears it) and its Workforce tests. Six mixed tests were split between the apps; the group rendering matrix keeps one shared fixture list (`@eddi/app-kit/test/group-message-matrix`).
- **The mock API is shared, not split.** Every MSW handler the Workforce screens call is also called by the Manager (the catalog included: `use-chat` reads it), so there was no Workforce-only set to drop; the handlers moved to `@eddi/app-kit/test/mocks`, and both apps' tests and dev servers run on them. The OpenAPI contract test stays in the Manager.
- **i18n** — the Manager's locale files were split by who uses each key: 1,133 keys to `@eddi/app-kit`, 613 to Workforce, 5,128 stay in the Manager, in all 11 locales. `check-i18n.mjs` moved to `ui/scripts/` and checks the app it runs from.
- **Guards** — `appBoundary` in `ui/eslint.config.base.js` (with the tests-must-fail rules, now shared as `signedInApp`) fails a Manager import of Workforce code and the reverse; `src/__tests__/app-boundary.test.ts` in each app checks resolved paths. `route-integrity` is a shared suite each app runs over its own table and the shared modules it renders, and fails a router link into the other app. `core/src/boundaries.test.ts` resolves relative paths (app-kit has `components/chat/` and `components/workforce/` of its own), keeps the three packages below app-kit from importing it, and checks that its `exports` reach every module.
- **The production bundles no longer carry the mock API.** `main.tsx` passes `startApp` the MSW loader as `import.meta.env.DEV ? () => import(…) : undefined`.
- **Build** — `pom.xml` builds `ui/workforce` (`workforce-build`), copies its `dist/` beside the Manager's (`workforce.html` at the root, chunks under `assets/`), cleans `ui/workforce/dist`, and `-DskipUi=true` skips it. The jar layout is unchanged: `RestWorkforceResource` still serves `workforce.html` for every `/workforce/**` path, so deep links and reloads (`?agentId=&conversationId=`) work as before, with no Java change. `ui/scripts/` now holds the shared build tooling (`vite-plugin-brand.mjs`, `vite-backend-proxy.mjs`, `install-playwright-chromium.mjs`); the dev proxy gained `/catalog`, which it never forwarded.
- **CI** — a `UI Workforce` job (app-kit type check and lint, lint, i18n, type check, tests, build, budget, MSW E2E) in the UI Gate; Build Image checks the packaged assets against both builds; the SBOM gains `bom-ui-workforce.json`; CodeQL scans `ui/workforce/src`; Dependabot's `/ui` entry already covered it.
- **Budgets** (`ui/bundle-budget.json`) — Workforce gets its own: 251.2 KB gz first load measured at the split (it loaded the Manager's whole 629.4 KB entry before), budget 280 KB. The Manager's first load fell from 629.4 to 604.1 KB gz with what left it (Workforce's strings above all), so its budget is lowered from 630 to 620 KB; the widget's is unchanged.

**Design decisions**

- *A fourth package rather than the plan's three.* The modules Workforce needs read the router, call the backend and read `window.__EDDI_*__`, which `@eddi/ui` and `@eddi/conversation` forbid; loosening those rules, or letting Workforce import the Manager, were the alternatives. `@eddi/app-kit` is app code shared by two apps; what phase 6 moves into `@eddi/conversation` (the team kind) leaves it.
- *Paths kept, not redesigned.* Modules kept their relative paths, so a Manager import changed from `@/x` to `@eddi/app-kit/x` and nothing else — reviewable, scriptable, and `git mv` keeps the history.
- *No index barrel.* The package's `exports` map directories, so an app's first load holds only what it reaches.
- *Rejected: `/workforce/index.html`.* The shells stay at the jar root as the backend expects (`BrandedShell`); a new layout would have needed Java and test changes for no user-visible gain.

**Follow-ups:** phase 6 (Operator and team kinds) drains the group components out of `@eddi/app-kit`; `use-current-screen-context.ts` still maps `/workforce` screens, which the Manager no longer renders.
