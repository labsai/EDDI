## fix(ui): review findings in the Manager and Chat UI — operator gate check, approval binding, hostile-input bounds (2026-10-31)

**Repo:** EDDI (`fix/review-ui`) — Manager (`ui/manager`) and Chat UI (`ui/chat`) only. The mechanical half of the same review (RTL icon mirroring, dead code, `chatKeys`) is on `chore/review-ui-cleanup`.

### What changed and why

**Platform Operator**
- `gateLooksInstalled` ([`operator.ts`](../../ui/manager/src/lib/api/operator.ts)) now judges a gate the way the backend's `ToolApprovalPatterns` matches it: `*` is a wildcard anywhere in a pattern. An `exempt` entry is refused when it can match any `http.{post,put,patch,delete}:/…` address (`*:*`, `h*`, `*post*`, `http.*:/x` all pass the old check and exempt every write at runtime, `exempt` being tested first), and the same test now applies to the AUTO_APPROVE `rules` check, which used to omit the `http.*:` prefix. `requireApproval` must cover **every** write method with a `<head>*` pattern — a PATCH-only gate used to certify an operator whose POST/PUT/DELETE calls ran unapproved. The gate `buildToolApprovals()` writes (all four methods, unchanged since it was introduced) passes, so no shipped operator is newly reported as ungated. A per-task `toolApprovals` override lives in the llmstore document and is not inspected here; the backend's default `strict` mode only lets it strengthen the agent gate. The verifier is outside the revision fingerprint (the prompt, allow-list and `buildToolApprovals()` are unchanged), so `operator-revision.json` stays at its value.
- The same judgement drives the `agentCreatedWithoutGate` approval warning, which now also fires for a gate covering only some write methods; its text (all 11 locales) says the gate does not cover every write method instead of claiming there is no gate.
- The operator chat's resume now carries a `pauseId` ([`use-operator-chat.ts`](../../ui/manager/src/hooks/use-operator-chat.ts), [`operator.tsx`](../../ui/manager/src/pages/operator.tsx)): the id of the pause the card showed, else the displayed pause's start, else the pause read just before the resume. If the displayed pause and the one read now differ, the decision is refused client-side. A top-level REJECTED could previously land on a pause nobody had looked at.
- The cascade approval preview reads `redeploy`/`compatible` the way Jackson's default coercion does — `"true"`, `"True"`, `"TRUE"` (trimmed) and any non-zero integer are true — so a redeploy requested in one of those forms no longer shows as none.

**Hostile or oversized input (Manager)**
- [`group-utils.ts`](../../ui/manager/src/components/groups/group-utils.ts): the markdown link-destination mask is bounded (`](` runs with no `)` rescanned the text from every opener, ~5 s per 100k characters); `maskIndentedCode` builds its line table once instead of re-splitting the prefix for every indented run; the ✅/❌ verification header is parsed with string steps and a per-line cap instead of a backtracking regex. `formatJsonSafely` (artifacts panel) returns content over 64 KiB or nested deeper than 32 as written. The sync diff viewer gives `diffLines` a time budget and falls back to one removal plus one addition.
- `useLatestVersions` counts only descriptors whose own id is the requested resource (the `filter=` search is a substring match); erasure also sweeps the `workforce-analytics` cache; a conversation loaded for one agent is refused when it belongs to another; selective export sends the snippet and schedule selections (an empty list means none) instead of exporting every one.

**Correctness**
- Agent config number fields keep a typed `0` (`pruneStaleAfterDays: 0` was saved as 90, the opposite of "never prune"); the Dream cost default shown is the backend's 0.50, not 5.
- "Switch to latest" is disabled while the editor holds unsaved edits. The Workforce settings page reads the group's **current** version when the URL names none (and offers Retry if the lookup fails), registers with the in-app navigation guard, and its delete flow (like the agent, channel and group-config delete flows) calls `allowNextNavigation()`. A deleted group discussion no longer re-selects itself while the list still holds it.
- The Variables page documents `{vars.key}` (Qute), not `{{vars.key}}`, in all 11 locales. RAG ingestion shows translated status labels (9 new `ragEditor.status*` keys, all 11 locales), polls for ~11 minutes (2 s, then 10 s) and then says "stopped checking" instead of declaring a failure while the server is still ingesting; `kbId`/`ingestionId` go through `seg()`.
- The deploy/undeploy button no longer acts on another agent's status shown as placeholder data. The tool-approval pattern validator accepts `/ { }` and method-qualified `http.<method>:` patterns like the backend and rejects the shapes it rejects. Upgrade preview and live sync send `X-EDDI-Space`; the cluster activity stream re-reads the bearer token on each reconnect. The update-check card now says the request origin is sent (a CORS fetch always carries `Origin`).
- Chat UI: `embed-auth` backs off (10 s doubling to 5 min) when the host keeps handing over an already-expired token, instead of re-requesting every 5 s forever.

### Design decisions

- `ui/manager/AGENTS.md` now says the app runs under a data router (`createBrowserRouter`), as `main.tsx` and §4b already did.
- The Variables page's unreachable `copyRef` template branch (it still builds `{{vars.key}}`) is left alone here: `chore/review-ui-cleanup` deletes it, and editing it on both branches would make the two PRs conflict.
