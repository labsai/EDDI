## 🎨 feat(manager): brand-aware strings, logos, titles, update UI and About — white-label phase 3 (2026-10-25)

**Repo:** EDDI (`feat/white-label-4-manager-strings`)

### What changed and why

Phase 3 of the [white-labeling plan](../../planning/white-label-ui-plan.md): the Manager names the brand instead of EDDI. Unbranded, everything reads and looks as before. [`docs/white-labeling.md`](../white-labeling.md) has a new "The Manager" section.

- **`src/lib/brand.ts`** reads `window.__EDDI_BRAND__` field by field, with the EDDI defaults for anything missing, so Vitest, the dev server and MSW mode need no backend. It is one store (`getBrand`, `setBrand`, `subscribeBrand`); components use `useBrand()` (`src/hooks/use-brand.ts`, `useSyncExternalStore`). `brand.test.ts` evaluates the Vite plugin's `DEFAULT_BRAND_SCRIPT` and requires it to equal `DEFAULT_BRAND`, which closes the chain Java = plugin = `brand.ts` that `BrandDeliveryTest` starts.
- **Strings.** `src/i18n/config.ts` sets `interpolation.defaultVariables = { productName, shortName }` before `i18nReady` resolves, and updates them in place (then re-announces the language) when `setBrand` runs, which is what Phase 4's live reload needs. Of the 77 English values naming EDDI, 63 product mentions became `{{productName}}` in all 11 locales by script; 12 engine-version gates ("Needs EDDI 6.6 or later", "This EDDI does not record…") were rewritten by hand to "server version" wording in every locale; 2 technical names stay (the `eddi-v1` webhook signature hint and the "EDDI Cluster" Grafana dashboard). 76 `t()` fallbacks in 45 files follow `en.json`. Eleven translations that had dropped the name, or named it once where English names it twice (`onboarding.tour.dashboard.step4Desc` in four locales, `syncPage.*` in three, one German sentence) were retranslated with the variable, because the interpolation-integrity test now sees it. The secrets API's English error no longer names EDDI.
- **Guard:** `src/__tests__/no-eddi-brand-literal.test.ts` fails on `\bEDDI\b` in any locale value, `t()` fallback, `defaultValue`, JSX text, or `alt`/`aria-label`/`title`/`placeholder` in `src` (tests, test mocks and comments excepted), after stripping `EDDI_*`, `X-EDDI-*` and `labsai/EDDI`. Its key allow-list holds the Powered-by notice and the two technical names, each with a reason. The Platform Operator's files are excluded with a TODO naming Phase 6.
- **Logos.** `components/layout/brand-logo.tsx` (`BrandWordmark`, `BrandIcon`) replaces the bundled data URI in both sidebars and `/eddi-icon.svg` on the landing page, the Workforce collapsed sidebar and the Workforce onboarding hero. The collapsed Manager sidebar shows `/branding/icon` when branded and the "E." monogram otherwise. Alt texts and labels are the product name.
- **Titles:** `use-document-title.ts` builds `<page> — <app.title>`, and `app.title` is `{{productName}} Manager`.
- **Update UI (R5):** `isUpdateUiVisible(brand)` (`!branded || showUpdateCheck`) gates the Updates nav entry and command-palette entry (through `useMayOpenScreen`), the `/manage/updates` route (redirects to `/manage`), the banner in `AppLayout`, and the automatic check itself (`useUpdateCheck`'s query is disabled), so a stored auto-check preference never contacts GitHub on a branded deployment.
- **About dialog** (`components/layout/about-dialog.tsx`), opened from the Help menu in the sidebar footer, and from the version label when the update UI is hidden: product name, tagline, version, and while `poweredBy` is on, "Powered by EDDI" with the Apache 2.0 notice and a license link. Six `about.*` keys in all 11 locales.
- **Dev entry.** `ui/manager/index.html`, which serves deep links under `npm run dev`, now loads `/branding/__brand__.js` before the bundle and `/branding/brand.css`, uses `/branding/icon` and the `%BRAND_PRODUCT_NAME%` placeholders; `vite-plugin-brand.test.ts` pins it.
- **Monaco:** the prompt editor's template-variable colours come from `--editor-template-variable(-light)` in `index.css`, read once at registration (`src/lib/css-color.ts`), with today's hex as the fallback.

### Design decisions

- **The light/dark logo trick depends on `branded`.** The bundled default for both `/branding/logo` and `/branding/logo-dark` is the white EDDI wordmark (the shells' loader shows `/branding/logo` on a dark background, so the default cannot be dark). Unbranded, the sidebar keeps one image with `invert dark:invert-0`, pixel for pixel as before. Branded, it shows the light and the dark slot as two images switched by the `.dark` class (a `<picture>` media query cannot see the app's theme) and never inverts, since inverting a colour logo produces its negative. Trade-off: a brand that sets only a name keeps the white EDDI wordmark, which is faint on the light sidebar. The settings page (Phase 4) can warn about that; `__brand__.js` does not say which slots are uploaded.
- **A failed `/branding/*` logo falls back to the bundled wordmark** (`onError`), so the design-system bundle, which has no server, still renders it; `src/assets/logo_eddi.png` therefore stays.
- **Engine-version gates name the server, not the brand.** "Needs Acme 6.6" would mix the brand with EDDI's version numbers; "server version 6.6" is true under any brand. The sidebar's version label does show `<product> <version>`, as the plan asks.
- **The update strings use `{{productName}}`** rather than an allow-list: they only show unbranded or when the brand opted in.
- **About sits in the Help menu** so it is reachable with the sidebar collapsed too. "Version" is a label beside the number rather than `Version {{version}}`, which would have counted as untranslated in German and French.

The full Vitest suite was not run locally.
