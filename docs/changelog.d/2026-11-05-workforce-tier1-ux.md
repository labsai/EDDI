## ✨ feat(workforce): Tier 1 of the end-user chat — Stop that tells the truth, edit and regenerate, rich output, attachments, keyboard, installable, accessible (2026-11-05)

**Repo:** EDDI · **Branch:** `feat/workforce-tier1-ux` (stacked on `feat/conversation-operator-team`)

The frontend half of phase 7 of the frontend unification plan (`planning/frontend-unification-plan.md` §2.5, §3, §4.2, §5 Tier 1): T1.5, T1.6 (part), T1.7, T1.8, T1.10–T1.14. Search (T1.3), the tool notice of T1.6 and tool cards (T1.9) wait for the backend's B3 and B6, built on another branch. The changes are in the shared controller and components, so the Manager's chat, Agent Studio, the Workforce chat and member thread, and the embeddable widget get them where they apply.

### What changed and why

- **Stop that says when it did not take (T1.5).** `POST /agents/{id}/cancel` stops a running turn only on the pod running it ([HITL](../hitl.md)); a `200` says the request was accepted, not that the turn stopped. [`AgentConversation`](../../ui/packages/conversation/src/controller/agent-conversation.ts) now re-reads the conversation after Stop (`stopVerifyDelaysMs`, 1.5 s and 5 s): a turn that ran on gets a notice — it *finished anyway* (its whole reply replaces the part Stop left) or is *still running* — a `409` means it had already finished, and a cancel that could not reach the server says that. A `409` is read from any host client's error now, not only `@eddi/core`'s `ApiError` (the Manager's was never recognised).
- **Reconnect (T1.5).** A stream that drops after part of the reply arrived is followed (`reconnectDelaysMs`, about half a minute; new `reconnecting` state): the conversation is re-read until the turn settles, and its reply is applied as its `done` would have been. "Connection lost" only when it never settles. Opt-in; the widget, `ChatPanel` and the member thread pass the shared defaults.
- **`ChatPanel` (Manager, Studio, Workforce).** Stop in place of Send while a turn runs, **Esc** stops it (not while a dialog is open), a "Reconnecting…" line, client notices as system lines (`ChatMessage` `kind: "notice"`), no pulsing bubble while text streams, a stable scrollbar gutter, the composer refocused after a send, a new chat and Stop. Sticky scroll with "jump to latest" was already there (`useSmartAutoScroll`).
- **Edit the last message, regenerate the last reply (T1.6, T1.10).** *Edit* (or **↑** in an empty composer) undoes the last step and puts its text back in the composer; *Regenerate* reruns it. Only when the agent's `conversationControls` allow undo (and redo); never for a secret turn or one that carried files. **`renderTurnNotice`** on `ChatPanel` is the seam for "this turn ran tools whose effects stay" once B6 reports which tools ran; no tool detection here.
- **Rich output (T1.7)**, in the one renderer ([`Markdown.tsx`](../../ui/packages/conversation/src/markdown/Markdown.tsx)): a fenced block names its language; a ```` ```mermaid ```` block is drawn by Mermaid with `securityLevel: "strict"` once its source has been still for 400 ms, and stays the code block until then or when it does not parse. [`MermaidDiagram.tsx`](../../ui/packages/conversation/src/markdown/MermaidDiagram.tsx) and Mermaid are lazy chunks in every app. Tables, code copy, message copy, KaTeX (`trust: false`) and images-as-links were in place. `one-renderer.test.ts` also forbids `mermaid` outside the renderer, and now reads `workforce/src` and `workforce/e2e`, which phase 5 had added without telling it.
- **Attachments (T1.8)** ([`use-attachment-staging.ts`](../../ui/packages/app-kit/src/hooks/use-attachment-staging.ts)): a file from 256 KB goes up through XMLHttpRequest and shows its own progress (bar and percentage); a failed chip keeps the server's reason, announced as an alert, with *Try again*. Paste, drop, picker, thumbnails and the cap were in place.
- **Keyboard in Workforce (T1.10).** ⌘K / Ctrl+K opens a [quick switcher](../../ui/workforce/src/components/workforce/quick-switcher.tsx) over the sidebar's chats and team sessions, the agents and "New chat" (combobox + listbox, a lazy chunk); ⌘⇧O / Ctrl+Shift+O goes Home with the composer focused. The shortcuts dialog lists every shortcut. The widget: Esc stops.
- **Installable Workforce (T1.11).** `GET /workforce/manifest.webmanifest` ([`WorkforceManifest`](../../src/main/java/ai/labs/eddi/ui/WorkforceManifest.java), `RestWorkforceResource#manifest`) renders the manifest from the current brand: name, short name, primary colour, the brand's icon slot (a PNG's real size from its header, an SVG `any`), standalone, scoped to `/workforce`. A literal JAX-RS path beside the catch-all; public like the shell. The shells link it, an `apple-touch-icon` and the theme colour, with `viewport-fit=cover, interactive-widget=resizes-content`; the layout pads by the safe-area insets and takes its height from the visual viewport while an iOS keyboard shrinks it ([`use-visual-viewport-height.ts`](../../ui/workforce/src/hooks/use-visual-viewport-height.ts)).
- **Accessibility (T1.12).** [`ReplyAnnouncer`](../../ui/packages/conversation/src/components/ReplyAnnouncer.tsx): a polite status region says each completed reply once, with its speaker, and the client's notices; the transcript `log` is `aria-live="off"` (it used to be live, with `aria-relevant="additions"`, which reads streamed text piecemeal). Muted text and controls in the chat no longer fade the token below contrast (`/40`–`/80` modifiers), with a guard test; the conversation-info toggle has a translated name and `aria-expanded`. Focus returns to the composer after a send, a new chat and Stop, and to where it was when the quick switcher closes.
- **Locales and themes (T1.13).** Every new string is in the eleven locales (5 in `@eddi/conversation`, 10 in `@eddi/app-kit`, 13 in Workforce); new layout uses logical properties; the new surfaces follow the light, dark and system themes through the shared tokens.
- **Ratings (T1.14)** were complete (thumbs per reply, reasons and a comment after a thumbs down); a test now pins the whole path through `ChatPanel`.
- **Widget budget.** The widget's first load must stay within 170 KB gz. `PausedCard`, `RatingCard` (new entries `@eddi/conversation/paused-card`, `/rating-card`) and `StepRating` now load when first shown, which pays for the new code: **169.4 KB gz** (it was 170.0).
- **Platform Operator.** The prompt learns how users install Workforce, that the manifest follows the branding, that there is no service worker on purpose, and what Stop does in a cluster. No allow-list change. `operator-revision.json` 54 → **55**.
- **Docs.** [`workforce-guide.md`](../workforce-guide.md) (while the agent answers, editing, what a reply can contain, files, ratings, keyboard, installing; for administrators: the manifest and Stop in a cluster), [`chat-ui-embedding.md`](../chat-ui-embedding.md) (§5, what the widget does during a reply), `ui/manager/AGENTS.md`, `ui/chat/AGENTS.md`, `ui/workforce/AGENTS.md`, the `@eddi/conversation` README.

### Design decisions

- **No service worker.** Browsers install without one, Lighthouse dropped its PWA category, and Workforce shows signed-in conversations that must never come from a cache; an app shell would only risk a stale UI after a deploy. An e2e test fails if any worker other than the MSW mock registers.
- **The manifest is rendered, not shipped.** A static file could not carry a deployment's name, colour or icon; rendering it from `BrandingService` follows a rebrand at once, as the shells do.
- **Stop is checked, not trusted.** Two re-reads after the cancel rather than one: the cancel's own mark (`EXECUTION_INTERRUPTED`) is what an immediate read sees even when the turn runs on elsewhere.
- **Reconnect follows the turn instead of reopening the stream:** the backend has no resumable stream; the conversation read is the source of truth.
- **Progress only from 256 KB.** A small file is up before a bar could show anything, and fetch stays the path the rest of the client uses.
- **Mermaid ~12.2.0, not 12.3.0** (three days old at the time); `securityLevel: "strict"`, rendered lazily as §2.5 asks. 112 packages enter the lockfile, all in lazy chunks.

### Not done

- **Lighthouse** (exit criterion: accessibility and PWA ≥ 95 on Workforce) was not run here: no Chrome for Lighthouse in this environment, and current Lighthouse (12+) has no PWA category at all. Verified instead: the manifest (Java and e2e tests), installability criteria by hand (name, icons, `start_url`, `display`, HTTPS from EDDI), live region and focus (unit tests), contrast (guard test). Run it with `npx lighthouse http://localhost:7070/workforce --only-categories=accessibility --view` against `./mvnw quarkus:dev` after a `./mvnw package`, signed in (or `npm run dev` in `ui/workforce`, which serves the mock API).
- **No axe** in the repo (neither vitest-axe nor `@axe-core/playwright`); adding one is a dependency decision left for the follow-up.
- The widget's composer has no paste, drop or per-file progress: its first load has 0.6 KB left.
- Ratings from Workforce are recorded with channel `manager` (`MANAGER_RATING_CHANNEL`): a `workforce` channel needs the backend's `KNOWN_CHANNELS`.
- Not run here: the Playwright specs (listed and type-checked; the local browser build does not match), Stryker (no file in its scope changed: only `system-prompt.ts` text and `operator-revision.json`).
