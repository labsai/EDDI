## feat(agent-tests): agent regression harness — golden conversations (2026-10-15)

**Repo:** EDDI (`feat/agent-test-harness`; WS6 Phase 6.1)

### What changed and why

EDDI had thousands of tests and none that asserted what an *agent* does. A config-driven engine records every turn — actions, properties, output, tool calls, cost — so a suite can assert exactly that, independently of how an LLM words its answer.

- **`AgentTestSuite` config resource** (`configs/agenttests`): a versioned document like every other config — scripted cases of turns, per-turn expectations, tool mocks, defaults (`toolMode`, `unmockedTools`, `repetitions`, `passRate`, `turnTimeoutSeconds`) and a per-run dollar ceiling (`maxCostPerRun`, default $1). `AgentTestSuiteValidator` refuses at save time (400) what a run could not honour: unknown modes, invalid or over-long regexes (500 chars), more than 200 cases / 50 turns per case / 20 repetitions / 2,000 turns per run.
- **`AgentTestRun` records** (`engine/agenttests`, collection `agenttestruns`): one document per run through `IResourceStorageFactory` at a single version (the `GroupConversationStore` pattern), so it works on MongoDB and PostgreSQL alike; listed per agent newest-first, pruned to a bounded number per agent.
- **`AgentTestRunner`** runs a suite against an agent version deployed to the `test` environment: one conversation per case repetition as user `agent-test:<runId>:<case>:<repetition>`, each turn through the non-streaming `say` with a per-turn timeout, judged from the stored memory afterwards (`actions`, properties, output text, `audit:tool_calls`, `audit:cost`, state). Repetitions run on virtual threads, at most `eddi.agent-tests.max-parallel-cases` (4) at once; the summed `audit:cost` (start turns included) is checked against `maxCostPerRun` before every turn. A HITL pause is an observable `conversationState`, after which the conversation is ended — the runner never waits for a human. Every test conversation is ended and permanently deleted afterwards (`RestConversationStore.purgeConversation`, the guard-free half of the permanent delete) unless the run keeps them. One summary audit-ledger entry per run (`taskId: ai.labs.agenttest`).
- **`ExpectationEvaluator`**: `actionsContain`, `actionsExact`, `properties` (`equals` — representation-tolerant, `3` = `"3"` — `matches`, `exists`, `absent`), `outputContains`, `outputMatches`, `toolCalled` (+ `argsSubset`), `toolNotCalled`, `maxToolCalls`, `maxCostUsd`, `conversationState`. Every failing expectation is reported with the expected and actual value.
- **ReDoS guard (`BoundedRegex`)**: no safe-regex helper existed. Patterns are capped at 500 characters at save time and matched against a `CharSequence` that throws after 250 ms, so a catastrophically backtracking pattern fails its expectation instead of occupying a thread.
- **Long-term user memory is neither read nor written by test conversations**: `ConversationService.createPropertiesHandler` hands an `agent-test:` user no user-memory store (so `Conversation` skips both the init load and `storePropertiesPermanently`), and the undo/redo long-term sync skips them.
- **`AgentTestService`** (shared by REST and MCP): reading the suite needs VIEW; the version under test is deployed to `test` through `IRestAgentAdministration.deployAgent(test, …, autoDeploy=false, wait)`, so the deploy's own EDIT check, space-reference guard and agent quota apply to the starter; a run is refused (409) when a newer version is also deployed to `test`, because new conversations start on the newest ready version. At most `eddi.agent-tests.max-concurrent-runs` (2) runs execute per node (429 beyond).
- **Tool mocking (`ToolMockRegistry`), fail closed.** Consulted at the three places a pipeline reaches the outside world: `ToolLoopRunner.executeSingleToolCallResult` before executor dispatch (every LLM tool source; the HITL resume path goes through the same method), `ApiCallExecutor.execute` (rule-triggered httpcalls — the mock replaces the `IResponse`, so `saveResponse`, retries and `postResponse` property instructions run on the mocked `{httpCode, body}` unchanged; fire-and-forget calls are not dispatched) and `McpCallsTask` (rule-triggered MCP calls — no server contact at all, not even tool discovery, unless the suite runs live). An unmocked call returns `{"status":"NOT_EXECUTED","reason":"no mock defined in test mode"}` (a 501 for httpcalls) and fails the case; `toolMode: live` / `unmockedTools: live` are explicit opt-ins. A test conversation the registry does not know — a turn still running after its run gave up — is refused too. Memory-writing tools never run live in a test. For every other conversation the hook is one string prefix check on the user id. The LLM-path hook is a self-contained early return directly after the call is traced, so the pending split of that method merges trivially.
- **Tool expectations see all three paths**: the registry records every intercepted call per turn (mocked, refused or live), and `toolCalled` / `toolNotCalled` / `maxToolCalls` are judged against that record rather than the LLM-only `audit:tool_calls` trace.
- **REST.** Suites: `/testsuitestore/testsuites` (URI `eddi://ai.labs.testsuite/testsuitestore/testsuites/{id}?version=N`, the v6 store convention; registered with the workspace access-index backfill). Runs: `POST /agenttests/runs` (202 with the `RUNNING` record), `GET /agenttests/runs/{runId}`, `GET /agenttests/runs?agentId=`. Both `eddi-admin`/`eddi-editor`, the deploy tier.
- **MCP.** `run_agent_tests`, `get_agent_test_run`, `list_agent_test_runs` (`McpAgentTestTools`, AUTHOR tier like `deploy_agent`); tool count 85 → 88.
- **Metrics.** `eddi_agent_tests_runs_total{status}`, `eddi_agent_tests_turns_total`, `eddi_agent_tests_run_duration_seconds`, charted in the Scheduling row of the Full Metrics Reference dashboard.
- **Docs.** New [`agent-testing.md`](../agent-testing.md) (concepts, JSON reference, mocking rules, CI `curl` recipe, EU AI Act evidence note); `mcp-server.md`, `metrics.md`, `configuration-reference.md` (`eddi.agent-tests.*`), `SUMMARY.md`.
- **Full-engine proof:** `AgentTestSuiteIT` (DevServices MongoDB) stores a suite over REST, starts a run against the deterministic rules-only `agentengine` fixture agent — the run deploys it to `test` itself — and reads back `PASSED` for a suite that holds and `FAILED` with the actual actions for one that does not. It found two defects the unit tests could not: MongoDB assigns a run's id only on its first write, and a turn's completion callback can run before the turn is stored, so a turn is now judged from the snapshot `say` completes with (detailed, current step) and only its internal `audit:cost`/model names — stripped from every client projection — are read from the stored step, waiting up to 5 s for it.
- **Platform Operator.** May read suites and runs and start a run (a gated write — it deploys to `test`, like the deploy it already has); it may not write suites. Prompt explains reading results and `unmockedTool`. `operator-revision.json` → 18.

### Review fixes

- **Unchecked purge moved out of the REST layer.** The permanent delete is now `ConversationPurgeService` (memory package); `RestConversationStore` calls `purge` only after its owner check and keeps no unchecked public method. The runner calls `purgeAgentTestConversation(conversationId, runId)`, which refuses any conversation whose user id is not `agent-test:<runId>:…` — the runner can only delete what it created. Nothing in the delete path reads a request identity (tested on an identity-less virtual thread, with a pending approval ended as a system actor).
- **Cluster mode is refused (409).** Mocks and runs live in one JVM and NATS cluster mode can route a test turn to another node. A call refused for want of a session on this node now says so (`no agent-test session on this node …`) instead of `no mock defined`.
- **PR review.** A run whose result cannot be stored (an oversized document, say) is replaced by a terminal `ERROR` record without the per-case detail, never left `RUNNING`; an output expectation's failure records the output cut at 2,000 characters like the turn's own; a suite read goes through the shared `RestVersionInfo.read` (`version=0` = current, null/negative checks); the purge treats the store's `null` for a missing conversation as already gone.
- **Orphaned runs.** A new `ABORTED` status: at startup, `AgentTestRunRecovery` marks every `RUNNING` run (none can be live yet) aborted with the reason and deletes its test conversations, found by their deterministic user ids.

### Design decisions

- **The test marker is the user id** (`agent-test:` prefix), not a new memory field: the `CONVERSATION_START` turn runs inside `startConversation` before the conversation has an id, and the user id is the one thing every seam (user-memory handler, tool loop, httpcall executor, MCP task) already has. The prefix only ever takes capabilities away, so it need not be unforgeable. `agent-test:` rather than the plan's `test:`, which a real deployment could plausibly use for real users.
- **`ToolMockRegistry` is static**, because the LLM tool loop is plain classes built by `AgentOrchestrator`; threading a CDI bean through would have changed a dozen constructors (and the pending `executeToolCall` split).
- **Runs are not versioned config** and live in their own single-version collection, pruned per agent (`eddi.agent-tests.max-runs-per-agent`, 50).
- **A newer version deployed to `test` refuses the run** instead of being undeployed: the runner never changes a deployment it did not make.
- **Suites are not yet part of agent export ZIPs** (maintainer decision) — follow-up.

### Known gaps and follow-ups

- Phase 6.2: generate a suite from a conversation, LLM-as-judge expectation, Manager page. Phase 6.3: optional deploy gate.
- Suites in agent export/import ZIPs and in agent sync.
- A run lives on the node that started it; if that node stops, the run is marked `ABORTED` at the next startup and must be started again.
