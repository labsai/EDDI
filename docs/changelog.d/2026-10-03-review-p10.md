## 🐛 fix(audit,logs): review follow-ups to the GDPR audit erasure (2026-10-03)

**Repo:** EDDI (`review/p10`, on top of `fix/gdpr-audit-memory`)

- **Erasure never reports `complete` on trust.** The redaction sweep pages by offset over a
  timestamp-sorted filter that its own writes shrink; a row stepped over (identical timestamps
  swapping places between reads) was neither redacted nor counted as failed. A final read of the
  rows still under the raw id now fails the `auditRedaction` step if any is neither redacted nor
  a kept compliance record.
- **Admin-action records pseudonymise whole path segments.** A user id that is also a path word
  (`admin`) or one letter rewrote the rest of the path; only segments after the resource root that
  equal the id are replaced now.
- **Database-log retention deletes in batches** of 10 000 rows on PostgreSQL, instead of one
  transaction over the whole history on the first sweep.
- Docs: another replica's audit write queue is not flushed by an erasure (re-run it to redact
  late entries); the PostgreSQL upgrade check covers `idx_audit_task`; the log-retention metric
  section no longer splits the audit-metrics explanation.
- **PR #952 review.** The admin-action filter's failure WARN sanitizes the request method, path
  and exception text (CWE-117, CodeQL log injection). A queued entry redacted on its way out of the
  write queue is verified before it is re-signed, and the marker records the observed verdict
  rather than `VALID`. The concurrent-insert cap refusal reports `count/cap`. Docs: LLM transport
  security depends on the configured base URL (`http://` is not refused); the ledger is described
  as append-only with the erasure-redaction exception rather than "immutable"; the log-retention
  sweep runs every `eddi.logs.db-retention-interval`; the export summaries no longer imply a
  complete bundle; the retention-sweeps dashboard panel shows its legend.
