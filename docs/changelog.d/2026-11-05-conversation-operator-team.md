## The team kind of conversation — frontend unification phase 6 (2026-11-05)

**Repo:** EDDI · **Branch:** `feat/conversation-operator-team` (stacked on `feat/workforce-app`, PR #1285)

Phase 6 of the frontend unification plan (`planning/frontend-unification-plan.md`, §3.2, §7): group discussions become the **team kind** of `@eddi/conversation`, the same controller and components in the Manager and in Workforce, and Workforce's two group transcript renderers become one. The **operator kind** did not move in this phase (below).

**What changed**

- **`@eddi/core/groups`** ([`groups.ts`](../../ui/packages/core/src/groups.ts)) — the discussion contract: every type a stored or live group discussion is made of (`TranscriptEntry`, `GroupConversation`, the decision, tasks, proposals, artifacts), the SSE events and payloads, the group constants and the display fallbacks for styles and entry types, moved out of `@eddi/app-kit`'s `lib/api/groups.ts`, which re-exports the module so no import changed. The group *configuration* type, its normaliser and the calls stay in app-kit (they reference app-only modules). The four HITL types a stored discussion carries about its pause moved to `core/hitl.ts`. Not re-exported from core's main entry, so the Chat UI never resolves it.
- **`GroupDiscussion`** ([`controller/group-discussion.ts`](../../ui/packages/conversation/src/controller/group-discussion.ts)) — the framework-free controller of one group's discussion: the state a run builds, `applyGroupStreamEvent` (the reducer every SSE event goes through), and start, approve-and-resume, continue a round, detach, Stop (the deferred Stop, 409 as already ended), reset and `whenAccepted`. A plain store (`subscribe`, `getSnapshot`) over a `GroupTransport`, with an optional host store. It is the code of `@eddi/app-kit`'s `use-group-discussion-stream.ts`, which keeps its whole API and now binds the controller (a transport over the apps' client, one controller per group writing its slot of `useGroupStreamStore`). New framework-free tests: `group-discussion.test.ts` (10). Every existing stream, board and workspace test passes unmodified.
- **`@eddi/conversation/team`** — the team components moved from `@eddi/app-kit` with `git mv`: `TaskBoard`, `DecisionRecordCard`, `StructuredTurnCard`, `StructuredEntryBody`, `NegotiationLedger`, `ArtifactsPanel`, `DiscussionInsights`, `HumanTurnBanner`, the overview (`PhaseRail`, `MemberRoster`, `ParticipationMatrix`, `InteractionMap`, `BidBoard`, `DiscussionOverview`, the view toggle) and the entry readers (`group-utils`, `group-entry-body`, `group-payloads`, `group-decision`, `discussion-styles`, `use-discussion-digest`, ISO durations). Router-free. Their strings (152 keys, nested `groups.*` as before) moved to the package's [`team/i18n/locales`](../../ui/packages/conversation/src/team/i18n/locales/en.json) in all eleven locales, merged by `withTeamLocales` from `setupAppI18n`; the translation-quality suite merges them too. `Badge` and the display helpers (`hashColor`, `getInitials`, `formatUsd`, `formatDuration`) moved to `@eddi/ui` (app-kit's `lib/utils` re-exports the helpers). `ConversationMarkdown` moved to `@eddi/conversation/i18next`.
- **One transcript in Workforce.** The history viewer (`conversation-viewer.tsx`) renders a stored discussion through the board's transcript (`board-transcript.tsx`, read-only and opened at the top) instead of its own copies of the question, member, synthesis, error and skipped cards and the phase separator. History now looks like the board, with its pins and "Ask more".
  Two Workforce coverage assertions named copy of the deleted cards ("Final Synthesized Answer", "No content") and now assert the board transcript's synthesis card and "No response generated"; the wave-3 parity test no longer looks for an icon map in the viewer (it has none) and checks that it renders through the board transcript. No other test assertion changed; the moved components' tests changed their import path only.
- **Links** in the September and October archives and one fragment pointed at the files that moved; they were repointed (link targets only).
- **`npm run i18n:check`** counts every `i18n/locales` directory of a package, not only `src/i18n/locales`.
- **Lockfile** — `@eddi/conversation` depends on `@eddi/ui`, `i18next` and `react-i18next` (already in the tree); the lockfile was regenerated in `node:26.13.0`.

**Not done in this phase, and why**

- **The Operator still runs its own turn loop** (`use-operator-chat.ts`). Moving it onto `AgentConversation` needs controller work first: an approval policy hook (resume with per-call decisions and request pinning, poll until the resumed turn settles, the 409 / `awaiting_approval` race that back-fills the ask, executed calls reconstructed from the detailed log). The 2,600 lines of operator store tests pin those call sequences, and the approval UI is security-reviewed. Nothing under `ui/manager/src/lib/operator`, in `lib/api/updates.ts` or `lib/hitl-tool-approvals.ts` changed, so the Stryker scope and the HITL guard tests are untouched. The Platform Operator's prompt and allow-list are unchanged (no operator-visible behaviour moved).
- **The Manager's group transcript** (`discussion-transcript.tsx`, `agent-response-card.tsx`) still renders its own entry cards, around the approval card and editor tools. Moving it onto the shared transcript changes how the Manager's workspace looks and its tests' markup, and is the next step, together with moving `board-transcript.tsx` and the advisor card into `@eddi/conversation/team` behind slots (pins and "Ask more" as `messageActions`).

```decision-log
| 2026-11-05 | The team kind lives in its own entry, `@eddi/conversation/team`, and its components keep react-i18next | The Chat UI's first load sits on its 170 KB budget, and the team components are rendered only by the two i18next apps; their 152 strings stay nested `groups.*` keys so no call site changed | Exporting from the main entry and trusting tree-shaking; converting every `t(key, fallback)` call to the package's `useConversationText` |
| 2026-11-05 | The group discussion contract moves to `@eddi/core/groups`, the configuration type stays in app-kit | The controller and the components need the contract and may not import app-kit; the configuration references team handoffs and the group HITL editor's config | Moving the configuration too (drags app-only modules into core); duplicating the types |
| 2026-11-05 | The Operator stays on its own loop this phase | AgentConversation has no approval-policy hooks yet, and the operator's store tests and security-reviewed guards must not change in the same step | Migrating it now with rewritten tests |
```
