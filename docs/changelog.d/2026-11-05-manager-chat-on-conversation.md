## 💬 refactor(manager): the Manager's chat on `AgentConversation` (2026-11-05)

**Repo:** EDDI (`refactor/manager-chat-on-conversation`, stacked on `feat/ui-eddi-conversation`)

Phase 3c of the frontend unification plan (`planning/frontend-unification-plan.md` §1.3, §2.5, §3.2, §7 phase 3): the Manager's 1:1 chat runs on [`@eddi/conversation`](../../ui/packages/conversation/README.md)'s controller, and every markdown surface in the UIs renders through the one renderer.

### What changed and why

- **Host hooks on `AgentConversation`** ([`agent-conversation.ts`](../../ui/packages/conversation/src/controller/agent-conversation.ts), [README](../../ui/packages/conversation/README.md#host-hooks)). The controller can keep its state in a host's store (`store`), follow a host's conversation generation (`generation`), let a replaced conversation's stream drain for a grace period before aborting it (`detachedGraceMs`), take undo/redo from `done` instead of a read (`refreshAfterStream: false`), show files as chips (`attachmentDisplay`, `send(text, secret, { attachments })`), read outputs a host's way (`outputTexts`), and hand events, turn boundaries, the finished snapshot, a failed turn's reason and every refusal or failure to the host (`onStreamEvent`, `onTurnStarting`, `onTurnEnd`, `onTurnSnapshot`, `turnFailure`, `presentFailure`). `send` resolves `{ outcome }`. Without the hooks it behaves as before; the widget's suites are unchanged. New rule for every surface: a secret turn never forwards an attachment.
- **`Message`** renders a sent message's attachments (image previews, file chips with size, "too large to send directly") and a reply's guardrail notes; **`ThinkingIndicator`** has a guardrail state (`guardrail`, `guardrailActive(messages, processing)`: "Checking the reply…") that the widget now shows. Eight `conversation.*` strings in the eleven locales (the guardrail lines are the Manager's existing translations). **`MarkdownContent`** gains `escapeRawHtml` (raw HTML shown as the text it is, for third-party text whose angle brackets are prose), and its image links carry `data-testid="markdown-image-link"`.
- **`ChatPanel` on the controller** ([`use-chat.ts`](../../ui/manager/src/hooks/use-chat.ts)). The Manager's send — streamed or not, the `done` reconcile, refusals, the detached-stream grace — is `chatConversation.send`; about 400 lines of its own turn loop (`handleSSEEvent`, `classifyRejectedSend`, `RejectedSendError`, the optimistic-message refs) are gone. The Zustand `useChatStore` stays the store every component reads: the controller writes it through `chatConversationStore`, and the store's own actions (agent picker, history, reset) advance the generation the controller follows. The Manager's copy is the hooks': a 409 is a pause only when a read confirms `AWAITING_HUMAN`, otherwise a toast; an error during a turn goes into the reply, flagged for "Retry Last Step"; a failed request keeps the message and adds an error bubble; the debug drawer gets every event (`recordDebugEvent`). The load guard, start, load/resume (with its masking of secret turns), following an executing turn, undo/redo/rerun and end stay Manager code. Every `use-chat*` and `use-send*` suite and every `ChatPanel` suite passes unmodified. That covers Agent Studio and Workforce chat, which render `ChatPanel`.
- **Visible in the Manager chat:** designer `image` output items render as images (live and from history; [`chat-message.tsx`](../../ui/manager/src/components/chat/chat-message.tsx)); `button` labels and `applicationLink` links in a reply are shown (@eddi/core's reader; the flat `output:text:*` keys are still read); a turn dropped into a paused or busy conversation is withdrawn with a notice instead of staying as sent; the thinking line stays on between pipeline tasks until the first token (it used to blink off at each `task_complete`); and a guardrail at work on the reply says "Checking the reply…" ([`guardrail-activity.tsx`](../../ui/manager/src/components/chat/guardrail-activity.tsx)).
- **The test drawer** ([`chat-drawer.tsx`](../../ui/manager/src/components/chat/chat-drawer.tsx)) sends through `useSendMessage` and reads `useChatStore`, so it runs on the controller with `ChatPanel`; it gains the guardrail activity line, and designer images through `ChatMessage`. Its own composer, quick replies and masked field are unchanged (`chat-drawer*.test.tsx` unmodified).
- **One markdown renderer, enforced (§2.5).** The thirteen Manager files that called `ReactMarkdown` themselves — the group transcript, response, structured-turn, decision and overview cards and the artifacts panel, the Workforce board, advisor card, context card, conversation viewer and member thread, the Operator chat, and the update check's release notes — render through `ConversationMarkdown` (`MarkdownContent`). Each keeps raw HTML escaped as it was (`escapeRawHtml`); what they gain is KaTeX, highlighted code with a copy button and scrolling tables. [`one-renderer.test.ts`](../../ui/packages/conversation/src/markdown/one-renderer.test.ts) fails on any import of `react-markdown`, `remark-gfm`, `rehype-raw`, `rehype-sanitize` or `rehype-katex` outside the renderer's directory, in either app or any package, tests included — no exceptions. `markdownImageAsLink` is gone from [`markdown-safe.tsx`](../../ui/manager/src/lib/markdown-safe.tsx) (the renderer has the same rule); `sanitizeAgentHtml` stays for the group card's opt-in HTML view. The update card's test now finds the image link by the renderer's test id.
- **Feature matrix** ([`feature-matrix.spec.ts`](../../ui/manager/e2e/feature-matrix.spec.ts)). Now assertions: `output-images` on the chat panel (an MSW reply with an `image` item, `IMAGE_OUTPUT_TRIGGER`), and `katex` and `highlight` on the Workforce member thread (the rich-markdown trigger, sent from the thread; its textarea gained `data-testid="thread-input"`). The operator's `katex` and `highlight` move from `no` to `unit`: it renders through the shared renderer, but the MSW tier has no activated operator.
- **Platform Operator.** No endpoint, field, default or failure mode changed, so neither its prompt nor its allow-list changed and `operator-revision.json` was not bumped; its chat only changed renderer. No Stryker-scoped file changed (`lib/operator/**`, `lib/api/updates.ts`, `lib/hitl-tool-approvals.ts`).

### Not done

- **The Workforce member thread's turn loop** (`workforce-thread.tsx`) is still its own: it renders through the one renderer now, but quick replies, the requested input field, secret input, designer images and the controller's turn rules reach it only when it sends through an `AgentConversation` of its own (an internal store, `presentFailure` for its error banner and Retry, `onTurnSnapshot` for its pause notice). Its matrix cells for those stay `no`.
- The matrix has no test-drawer column: the MSW tier cannot open the drawer without the save-and-deploy flow. The drawer shares the chat panel's controller and bubble.
- Start, load/resume, undo, redo and rerun in `use-chat.ts` are not the controller's yet: they install snapshots with the Manager's secret masking and attachment-preview carry-over, which the controller's `stepsToMessages` does not do.
