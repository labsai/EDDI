## ✨ feat(events): the per-user event stream, `GET /me/events` (2026-11-06)

**Repo:** EDDI · **Branch:** `feat/user-event-stream` (from `feat/conversation-search-tool-ui`)

Phase 8 of the frontend unification plan (`planning/frontend-unification-plan.md` §6, **B12**), the backend for T2.3 (approvals in the flow) and T2.8 (long jobs with a notification when done). A server-sent event stream that tells a signed-in user's tabs about things that concern them, plus a framework-free client in `@eddi/core/user-events`. No UI yet: the next step wires the notifications.

### What changed and why

- **`GET /me/events`** ([`IRestUserEvents`](../../src/main/java/ai/labs/eddi/engine/userevents/IRestUserEvents.java), [`RestUserEvents`](../../src/main/java/ai/labs/eddi/engine/userevents/RestUserEvents.java)): a `ready` frame, then one named event per thing — `approval.pending`, `approval.decided`, `team.started`, `team.waiting_for_human`, `team.ended`, `job.finished`, `job.run_completed`, `job.failed`, `notification.created` — and a keep-alive comment every 20 s. Any role may open it; an anonymous caller gets `401` with authorization on (`@RolesAllowed` first, an explicit check second).
- **Ids and kinds, never content** ([`UserEvent`](../../src/main/java/ai/labs/eddi/engine/userevents/UserEvent.java)): conversation, agent, group, discussion, schedule and notification ids, plus short enum states. No message text, title, prompt, pause reason, tool argument or display name; the client fetches details through the access-checked endpoints. Tests serialize every group state with a question, an answer, a pause reason and a rendered prompt set, and find none of them on the wire.
- **Scoping at fan-out, per connection** ([`UserEventHub`](../../src/main/java/ai/labs/eddi/engine/userevents/UserEventHub.java), [`UserEventAudience`](../../src/main/java/ai/labs/eddi/engine/userevents/UserEventAudience.java)): each event carries an audience read from the authoritative record (the conversation descriptor's owner, the discussion's owner and `HUMAN` roster, the notification's recipient), and each connection is checked against it with what its own request established — principal, `eddi-admin` / `eddi-approver`, team subjects — plus, for a paused 1:1 conversation, a fresh `ResourceAccessGuard.checkPrincipalUse` on the agent (the rule `HitlAccessGuard.requireConversationResumeAccess` applies to an owner's resume). A check that cannot answer delivers nothing. Approvers and admins get approval events by role, as [Who May Decide](../hitl.md#who-may-decide) says.
- **Sources.** `approval.pending` (1:1) from `HitlPauseCommittedEvent`; `approval.decided` (both surfaces) from `HitlDecisionRecorded`; group gates and `team.*` from `GroupConversationService.executeDiscussion` (start of a fresh leg, and the end of every leg, reading the state the leg left behind) and the cancel of a paused discussion in `GroupHitlCoordinator`; `job.finished` from `ConversationContinuations.armIfDecided` when a continuation turn arms no successor (state `done`, or the refusal reason); `job.run_completed` / `job.failed` from `ScheduleFireExecutor` (the owner read from the conversation descriptor, never the schedule); `notification.created` from `WorkspaceNotifications.deliver`, `UPDATE_AVAILABLE` to every admin.
- **Cluster.** [`UserEventPublisher`](../../src/main/java/ai/labs/eddi/engine/userevents/UserEventPublisher.java) delivers locally and publishes `ClusterEvent.USER_EVENT` on the existing `IClusterEventBus` (JetStream with `eddi.messaging.type=nats`, a no-op in-memory); each receiving node scopes the event against its own connections. Principals travel as `KvKeys.sha256` hashes, as the other user-keyed cluster events do. A kind a node does not know is dropped.
- **Bounds.** Per-user (`8`) and per-node (`10000`) connection caps answering `429` with `Retry-After`. Before refusing, the caller's own streams whose client already went away are swept under the registration lock (only that caller's bucket, never a global scan), so a reload or a flaky network is not refused by its own dead tabs, and two concurrent opens at one below a cap cannot both pass it; one fan-out thread behind a bounded queue (dropped and counted when full); a per-connection buffer of unacknowledged frames (`64`), past which the stream is closed as a slow consumer; streams closed at token expiry and after `max-connection-age` (1 h) so captured roles are re-read; a vanished client noticed at the next heartbeat. Seven `eddi.user-events.*` properties in `application.properties` and [configuration-reference.md](../configuration-reference.md).
- **Authorization off:** every caller is owner and admin, as on every other endpoint, so all streams share one anonymous bucket and get every event. That bucket is exempt from the per-user cap, which there would cap every caller of the deployment together; the per-node cap still bounds it.
- **Metrics:** `eddi_user_events_connections`, `eddi_user_events_delivered_total{kind}`, `eddi_user_events_dropped_total{reason}`, `eddi_user_events_rejected_total{reason}` — [metrics.md](../metrics.md#user-event-stream-metrics), a **User event stream** row on the Full Metrics Reference dashboard, and the Kubernetes copies (`scripts/sync-monitoring-assets.py`).
- **Frontend.** [`@eddi/core/user-events`](../../ui/packages/core/src/user-events.ts), its own `exports` entry, not re-exported from the root: `getUserEventStream` (one per tab), typed events, `on(kind | "*")`, `onStatus` (`open` means refetch), `fetch` through the app's `HttpClient` (bearer token and one refresh on `401`), reconnect with exponential backoff and jitter, stop on `401`/`403`/`404`, at least the server's `retryAfterSeconds` on `429`. A test fails if `ui/chat/src` ever imports it. MSW: [`user-event-handlers.ts`](../../ui/packages/app-kit/src/test/mocks/user-event-handlers.ts) holds the stream open after `ready` and writes whatever `pushMockUserEvent` sends; `GET /me/events` is in `openapi-operations.json`.
- **Docs.** New [user-events.md](../user-events.md) (in `SUMMARY.md`); [rest-api-reference.md](../rest-api-reference.md), [hitl.md](../hitl.md), [group-conversations.md](../group-conversations.md) and [long-jobs.md](../long-jobs.md) link to it.
- **Platform Operator.** The prompt explains the stream (kinds, audiences, limits, cluster behaviour, metrics, the audit-ledger dependency of `approval.decided`). No allow-list change: a stream is no tool. `operator-revision.json` → **57**.
- **Platform Operator, caps.** The prompt also says the per-user cap does not apply to the shared anonymous bucket with authorization off (only the node cap does); revision stays 57, fingerprint updated.

### Design decisions

- **Hints, no replay.** `Last-Event-ID` is not supported: a replay would need a per-user history shared across pods. The client refetches on every (re)connect instead, so a missed event is never lost in effect.
- **The audience is data; the decision is the receiver's.** The raising node names who may receive an event; every node, its own included, checks its connections against that with their own captured identity.
- **The end of a group leg reads the persisted state** instead of listening to each branch's listener call, so a new way of ending a discussion cannot forget to tell anyone.
- **`approval.decided` rides `HitlDecisionRecorded`**, which carries the owner and covers both surfaces, cancels and timeouts; the price is that it needs the audit ledger (on by default), which the docs and the operator say.
- **Refuse at the cap, not evict the oldest:** eviction would let two misbehaving tabs knock each other off in a loop; a refused tab backs off, and a closed tab's slot frees as soon as another stream is opened at the cap (otherwise at the next heartbeat).

### Not done

- The UI (T2.3 / T2.8 notifications) — the next step.
- Web push.
- No `*IT`: the cross-pod path is covered through the bus abstraction (two hubs joined by a fake bus with a JSON round trip), not against a live NATS.

```decision-log
| 2026-11-06 | `/me/events` events are hints with no replay; clients refetch on (re)connect | A replay needs a per-user history shared by every pod; a refetch already shows the outcome of anything missed | `Last-Event-ID` with a per-node ring buffer |
| 2026-11-06 | Each node scopes cluster-delivered user events against its own connections; principals travel hashed | The audience is data from the authoritative record; entitlement is decided where the connection's identity is | Sending per-user copies addressed by raw user id |
| 2026-11-06 | A stream over the per-user cap is refused with 429, not the oldest evicted | Eviction lets misbehaving tabs knock each other off in a loop; a closed tab's slot is swept when the user opens a stream at the cap | Evicting the oldest stream |
| 2026-11-06 | The anonymous bucket (authorization off) is exempt from the per-user stream cap; the node cap still applies | Every caller shares that bucket, so a per-user cap there caps the whole deployment | Applying the per-user cap to it |
```
