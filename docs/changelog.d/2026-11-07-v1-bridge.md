## 🐛 fix(openai): a stateless stream refused a permit ends its conversation; mapping deletes match (2026-11-07)

**Repo:** EDDI (`fix/v1-bridge`)

### What changed and why

Three defects in the OpenAI-compatible `/v1` adapter, found in the whole-codebase review.

- **A stateless stream refused a concurrency permit left its conversation open.** `prepare()` starts a stateless turn's throwaway conversation before the response is returned, and only `bridge.stream()` ended it. The streaming body takes its own permit; when it could not get one, it wrote the in-band `429` error event and returned without calling `stream()`, so every such request under `max-concurrent-requests` load left an open conversation behind. The new `OpenAiConversationBridge.abandon(turn)` ends a stateless turn's conversation (a stateful turn's belongs to its chat and is left alone), and the refused body calls it before writing the error.
- **Mapping deletes were unconditional, so concurrent requests could split a chat.** When a chat's mapped conversation had ended, Open WebUI's completion and title requests both found the stale mapping; the slower one's `deleteUserConversation` removed the fresh mapping the faster one had just written, and the chat continued in a second conversation while the first stayed open and orphaned. Every mapping delete in the bridge now goes through `deleteUserConversationIfMatches` with the conversation the request found unusable — the same primitive Slack and the webhook handler already use — so the slower delete is a no-op, its create collides, and the existing insert-conflict re-read adopts the winner.
- **Model resolution probed access by exception, and a failed catalogue was cached.** `AgentModelResolver.mayUse` caught `requireAgentUseAccess`, which logs a WARN and builds a `ForbiddenException` per hidden agent; `GET /v1/models` is polled, so a deployment with many private agents filled the log on every listing. It now asks `ResourceAccessGuard.hasAccess(id, USE)`, which answers the same. Separately, a failed `getAllLatestAgents` produced an empty catalogue that Caffeine stored for `model-cache-seconds`, so one store error made every model unknown for 30 s; the loader now returns `null` on failure (not cached) and the call that saw it gets an empty view.

### Design decisions

- `abandon` is a bridge method rather than an `endConversation` call in the adapter: the bridge owns the stateless-turn lifecycle (`say` and `stream` end it in their `finally`), so the adapter never needs to know which turns own a throwaway conversation.
- The conversation-id response header and the prepare-time start are kept, so a stateless streamed turn still names its conversation.
- Scope of the stream fix: it covers **one** way a `/v1` stream body can give up before `stream()` — the body runs but is refused a permit. Nothing else on the branch has the same create-then-stream shape: the native `/agents/{id}/stream`, its resume twin and the group-discussion streams take an `SseEventSink` and do their work in the resource method itself, so there is no deferred body to skip; the A2A streamed send's body only drains a queue, and the turn settles and releases its slot on its own (`RestA2AEndpoint.stream`); the ratings CSV export creates nothing before its body; the `/v1` permit is already released by the resource method and re-acquired inside the body; and a stateful `/v1` turn's conversation belongs to its chat and is reused.
- **Known gap — a body that never runs at all is not covered (no owner yet).** RESTEasy Reactive skips every remaining cancellable handler once the connection closes (`ResteasyReactiveRequestContext.isHandlerCanceled`), and `ResponseWriterHandler`, which invokes the `StreamingOutput`, is cancellable. So a client that disconnects after `prepare()` has started a stateless conversation but before the response is written still leaves that conversation open, until the idle sweep (`maximumLifeTimeOfIdleConversationsInDays`) ends it. Closing that window needs a response-completion hook on the Vert.x response, which cannot be checked without a live server; it is left as a follow-up rather than guessed at. PR #1404 (cancel a `/v1` stream's turn when its client leaves) does not close it either: its checks live inside `stream()`, which such a body never reaches.

### What's next

- End a stateless streamed turn's conversation when its response is disposed without the body having run (the disconnect window above).
